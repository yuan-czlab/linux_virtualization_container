# 故障注入脚本集合（教师用）

> 每个故障包含：注入命令 / 学生看到的现象 / 排查线索 / 修复命令
> 使用时直接复制粘贴对应命令即可

## 模块二：网络与远程管理

### F2-01：停止 sshd 服务

```bash
# 注入
sudo systemctl stop sshd

# 现象：ssh 连接断开，新连接 Connection refused
# 排查：systemctl status sshd → inactive
# 修复：sudo systemctl start sshd
```

### F2-02：修改 SSH 端口

```bash
# 注入
sudo sed -i 's/^#Port 22/Port 2222/' /etc/ssh/sshd_config
sudo systemctl restart sshd

# 现象：ssh -p 22 连不上，Connection refused
# 排查：ss -tlnp | grep ssh → 看到 2222 端口
# 修复：ssh -p 2222 user@host，或改回 22
```

### F2-03：防火墙拦截 HTTP

```bash
# 注入
sudo firewall-cmd --remove-service=http --permanent
sudo firewall-cmd --reload

# 现象：本机 curl localhost 通，外部浏览器打不开
# 排查：firewall-cmd --list-all | grep http → 空
# 修复：sudo firewall-cmd --add-service=http --permanent && sudo firewall-cmd --reload
```

### F2-04：错误 DNS 配置

```bash
# 注入
sudo cp /etc/resolv.conf /etc/resolv.conf.bak
echo "nameserver 1.2.3.4" | sudo tee /etc/resolv.conf

# 现象：ping 8.8.8.8 通，ping www.baidu.com 不通
# 排查：cat /etc/resolv.conf → DNS是1.2.3.4
# 修复：sudo cp /etc/resolv.conf.bak /etc/resolv.conf
```

### F2-05：/etc/hosts 错误条目

```bash
# 注入
echo "127.0.0.1 www.baidu.com" | sudo tee -a /etc/hosts

# 现象：ping www.baidu.com 返回 127.0.0.1
# 排查：cat /etc/hosts | grep baidu → 有错误条目
# 修复：sudo sed -i '/www.baidu.com/d' /etc/hosts
```

### F2-06：网卡 down

```bash
# 注入
sudo ip link set ens33 down

# 现象：ping 任何地址都不通
# 排查：ip a → ens33 state DOWN
# 修复：sudo ip link set ens33 up
```

### F2-07：SELinux 阻止 Nginx（经典 403）

```bash
# 注入
sudo chcon -t user_home_t /usr/share/nginx/html/index.html

# 现象：curl localhost → 403 Forbidden
# 排查：sudo ausearch -m avc -ts recent | grep denied
# 修复：sudo restorecon -v /usr/share/nginx/html/index.html
```

## 模块三：企业服务部署

### F3-01：Nginx 配置语法错误

```bash
# 注入（在配置文件中删一个分号）
sudo sed -i 's/;$//' /etc/nginx/conf.d/admin.conf
# 或直接加一行垃圾文本：echo "garbage" | sudo tee -a /etc/nginx/nginx.conf

# 现象：nginx -t 报错，reload 失败
# 排查：nginx -t 会指明错误行号
# 修复：编辑文件修复语法，nginx -t && systemctl reload nginx
```

### F3-02：Nginx 服务停止

```bash
# 注入
sudo systemctl stop nginx

# 现象：curl localhost → Connection refused
# 排查：systemctl status nginx → inactive
# 修复：sudo systemctl start nginx
```

### F3-03：MariaDB 停止

```bash
# 注入
sudo systemctl stop mariadb

# 现象：mysql -u root -p → Can't connect to local MySQL server
# 排查：systemctl status mariadb → inactive
# 修复：sudo systemctl start mariadb
```

### F3-04：MySQL root 密码错误

```bash
# 注入（修改 root 密码但不告诉学生）
sudo mysql -e "ALTER USER 'root'@'localhost' IDENTIFIED BY 'WrongPass999!';"

# 现象：mysql -u root -p 输入原密码 → Access denied
# 排查：检查是否输错了（实际密码被改了）
# 修复：通过安全模式重置密码，或恢复快照
# 教学点：平时要打快照！
```

### F3-05：Redis 密码被修改

```bash
# 注入
sudo sed -i 's/^requirepass .*/requirepass WrongRedisPass!/' /etc/redis/redis.conf
sudo systemctl restart redis

# 现象：redis-cli -a RedisPass2026! PING → NOAUTH 或 invalid password
# 排查：检查 /etc/redis/redis.conf 中的 requirepass
# 修复：改回正确密码或重新设置
```

### F3-06：Redis 无密码漏洞（安全审计题）

```bash
# 注入
sudo sed -i 's/^requirepass .*/# requirepass disabled/' /etc/redis/redis.conf
sudo sed -i 's/^bind 127.0.0.1/bind 0.0.0.0/' /etc/redis/redis.conf
sudo systemctl restart redis

# 现象：从外部 redis-cli -h IP PING → PONG（无需密码！）
# 排查：检查 redis.conf 安全配置
# 修复：恢复密码、恢复 bind 127.0.0.1、启用 protected-mode
# 教学点：这就是公网 Redis 被入侵的原因
```

### F3-07：Git 仓库文件被误删

```bash
# 注入
cd ~/web-project
rm -f index.html

# 现象：git status → deleted: index.html
# 排查：git status 会告诉哪些文件被删了
# 修复：git checkout -- index.html（从仓库恢复）
```

### F3-08：数据库表被误删

```bash
# 注入（做好备份先！）
mysql -u root -p company_db -e "DROP TABLE employees;"

# 现象：SELECT * FROM employees → Table doesn't exist
# 排查：SHOW TABLES; → employees 表不见了
# 修复：从备份恢复 mysql -u root -p company_db < backup.sql
# 教学点：备份的重要性！
```

### F3-09：端口冲突

```bash
# 注入
sudo python3 -m http.server 80 &

# 现象：Nginx 启动失败 → Address already in use
# 排查：ss -tlnp | grep :80 → 看到 Python 占用了 80
# 修复：kill PID，重启 Nginx
```

```bash
# 注入（先备份，再破坏）
sudo cp /etc/libvirt/qemu/VM名.xml /etc/libvirt/qemu/VM名.xml.bak
sudo sed -i 's/<name>.*<\/name>/<name>broken<\/name>/' /etc/libvirt/qemu/VM名.xml
```

## 模块五：Docker容器化

### F5-01：Docker 服务未启动

```bash
# 注入
sudo systemctl stop docker

# 现象：docker ps → Cannot connect to the Docker daemon
# 排查：systemctl status docker → inactive
# 修复：sudo systemctl start docker
```

### F5-02：镜像拉取失败

```bash
# 现象：docker pull 速度极慢或超时
# 排查：ping registry-1.docker.io → 可能不通
# 修复：配置镜像加速器 /etc/docker/daemon.json
```

### F5-03：端口已被占用

```bash
# 注入
docker run -d --name blocker -p 80:80 nginx:alpine

# 现象：第二个容器 docker run -p 80:80 ... → port is already allocated
# 排查：ss -tlnp | grep :80 或 docker ps | grep :80
# 修复：换端口，或 docker rm -f blocker
```

### F5-04：Volume 权限问题

```bash
# 注入
mkdir /tmp/docker-test
sudo chown root:root /tmp/docker-test
sudo chmod 700 /tmp/docker-test

# 现象：docker run -v /tmp/docker-test:/data alpine touch /data/test → Permission denied
# 排查：ls -ld /tmp/docker-test → 权限700，owner root
# 修复：chmod 755 或 chown student
```

### F5-05：容器启动后立即退出

```bash
# 现象：docker run alpine → 启动即退出，docker ps 看不到
# 排查：docker ps -a → Exited (0)，docker logs 无输出
# 原因：alpine 默认 CMD 是 sh，没有交互就退出
# 修复：docker run -it alpine sh 或 docker run -d alpine sleep 3600
```

### F5-06：容器网络不通

```bash
# 注入：两个容器在默认 bridge 网络
docker run -d --name c1 nginx:alpine
docker run -d --name c2 nginx:alpine

# 现象：docker exec c2 ping c1 → ping: bad address
# 排查：docker network inspect bridge → 没有 DNS
# 修复：创建自定义网络 docker network create mynet，把容器接入
```

### F5-07：Compose YAML 缩进错误

```bash
# 注入（在 compose.yaml 中用 Tab 替代空格）
# 教师手动编辑 compose.yaml，把某行空格缩进改为 Tab

# 现象：docker compose up -d → YAML parse error
# 排查：检查缩进——必须用空格，不能用 Tab
# 修复：把 Tab 改为空格
```

### F5-08：Compose depends_on 问题

```bash
# 现象：docker compose up -d → backend 启动时 MySQL 还没就绪，连接失败
# 排查：docker compose logs backend → Connection refused to db:3306
# 原因：depends_on 只等容器启动，不等服务就绪
# 修复：在 backend 代码中添加重试逻辑，或添加 healthcheck
```

### F5-09：docker compose down -v（数据丢失）

```bash
# 场景（教师演示，不要真删学生数据）：
# 1. docker compose up -d → 创建数据
# 2. docker compose down -v → 数据被删！
# 3. docker compose up -d → 数据全空了

# 教学点：-v 会删除 volumes！生产环境慎用！
```

## 使用说明

1. **注入前**：确保学生环境已保存快照或 Git 已提交
2. **注入方式**：教师通过 SSH 或直接在学生 VM 上执行
3. **排障时间**：每个故障给 10-15 分钟
4. **修复后**：教师验证修复结果
5. **重置环境**：通过快照恢复，或教师执行修复命令
