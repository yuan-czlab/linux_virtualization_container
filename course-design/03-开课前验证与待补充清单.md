## 课程链路级实机验收

单项软件“能安装”不足以证明课程可上。开课前至少选择一组机位，从前序检查点按下列顺序完成一次不跳步的冒烟测试，并记录每段实际耗时和失败恢复时间。

| 顺序 | 起点与范围 | 必须形成的通过证据 |
|---:|---|---|
| 1 | `Linux-L0`→实验2—7 | `~/m1-project`、账号权限、包管理、systemd日志和巡检结果均由步骤真实创建，形成`Linux-L1` |
| 2 | `Linux-L1`→实验8—13 | 三机静态地址与hosts一致，`course-env.sh`可读取，SSH、备份、firewalld、SELinux和故障恢复通过，形成`Linux-L2` |
| 3 | `Linux-L2`→实验14—19 | Nginx、MySQL、MongoDB、Redis、Git和巡检脚本均完成“功能+日志/数据+恢复”验收，形成`Linux-L3` |
| 4 | `Linux-L3`→实验20 | 三机链路和随机故障完整走通，恢复后服务仍可用，形成`Linux-L4` |
| 5 | `Linux-L4`→实验1—5 | 不删除Linux资产；完成嵌套KVM、客户机、qcow2、网络与OpenStack基础操作，形成`VC-V1` |
| 6 | `VC-V1`→实验6—10 | Rocky与Ubuntu使用同一固定镜像集；离线导入、网络、卷、Dockerfile和Compose完整通过，形成`VC-V3` |
| 7 | `VC-V3`→实验11 | Kubernetes个人命名空间操作、Ubuntu到Rocky离线迁移、数据恢复、随机故障和答辩材料全部通过 |

每段测试还必须做一次“关闭终端后继续”：重新登录并按手册中的`source`或起点检查继续任务，以发现只存在于旧Shell中的临时变量。每个`cd`目标、被修改文件和被恢复对象都应在本实验前序步骤创建，或在“状态依赖”中明确列出；不能为通过测试临时创建同名空对象。

仓库提供五类自动检查工具：

- `python tools/validate_course.py`：在教师电脑检查文档结构、31个实验的建议学时、代码块、XMind、跨终端变量及关键Compose/Kubernetes配置；系统具备Bash时还会自动执行隔离的文件工作流冒烟测试。
- `bash tools/smoke-filesystem-workflows.sh`：不需要root和网络，在临时目录实际验证文件创建、复制、移动、归档、恢复、PID保护和跨主机离线包所需的相对路径SHA256清单。
- `powershell -ExecutionPolicy Bypass -File .\tools\host-preflight.ps1 -CourseStage Linux`：在Windows宿主机检查VMware、VMnet8、NAT/DHCP、硬件资源，并可进一步核对VMX、ISO及`Linux-L0`；第二门课前使用`-CourseStage Virtualization`核对资源升级、嵌套虚拟化和`Linux-L4`。
- `bash tools/ssh-course-audit.sh 角色,IPv4,规范用户名 ...`：三机启动后，使用仅存在于当前进程环境中的课堂密码，只读核对实际登录账号、主机名、发行版、地址、SSH和VMware Tools状态。
- `bash course-preflight.sh 检查点`：复制到课程VM后，对`linux-l0`至`final`的真实对象和服务做只读核验。

自动检查不能代替功能访问、数据恢复、故障排查、VMware快照恢复和课堂计时，但可以阻止缺目录、缺文件、错检查点或服务未启动的环境继续进入下一阶段。

### 共享参数文件快速核验

在相应主机执行以下只读检查；任一命令失败都应先恢复检查点或修正参数，不继续后续实验：

```bash
test -r ~/m1-project/course-env.sh
source ~/m1-project/course-env.sh
[[ -n "$ROCKY_SERVER_IP" && -n "$ROCKY_WEB_IP" && -n "$UBUNTU_CLIENT_IP" ]]
printf '%s\n' "$ROCKY_SERVER_IP" "$ROCKY_WEB_IP" "$UBUNTU_CLIENT_IP"
getent hosts rocky-server rocky-web ubuntu-client
```

进入第二门课程后，在Rocky及进入Docker阶段的Ubuntu分别核验：

```bash
test -r ~/vc-course/course-env.sh
source ~/vc-course/course-env.sh
grep -n "CHANGE_ME" ~/vc-course/course-env.sh || true
[[ "$COURSE_REGISTRY" != 'CHANGE_ME' && "$COURSE_TAG" != 'CHANGE_ME' ]]
printf 'registry=%s tag=%s media=%s\n' \
  "$COURSE_REGISTRY" "$COURSE_TAG" "$COURSE_MEDIA"
```

`grep`仍有输出不一定代表课程第一天失败，因为OpenStack、Kubernetes参数可在对应实验前填写；但本阶段即将使用的变量不得仍为`CHANGE_ME`。不得把密码、Token或私钥写入共享参数文件或验证记录。
