## 二、机房还原与课程状态恢复

### 1. 开课前必须确认还原范围

不能假定VMware快照一定能跨重启保留。快照依赖虚拟机目录中的磁盘和描述文件；如果还原系统会恢复该目录，快照也会一起回退或消失。正式开课前使用一台测试机完成以下验证：

```text
□ 确认系统盘、数据盘和共享目录中哪些位置会被还原
□ 在计划存放VM的位置建立测试文件，重启后确认是否保留
□ 建立一台测试VM和一个快照，重启后确认VM与快照是否保留
□ 在VM内部建立标记文件，重启后确认虚拟磁盘写入是否保留
□ 记录固定机位、换机和损坏机器时的恢复流程及所需时间
```

如果VM目录可以放在非还原数据盘，学生以固定机位和模块快照延续实验；如果全部本地磁盘都会还原，则由教师在网络共享、移动硬盘或统一分发系统中保存关机状态的课程检查点VM，课前恢复到本地后再上课。项目报告、脚本、配置模板、数据库逻辑备份和容器交付包还应单独保存，但这些小型成果不能替代包含用户、软件包、systemd、网络和安全配置的完整VM状态。

### 2. 课程检查点

| 检查点 | 建立时机 | 必须包含的状态 | 主要用途 |
|---|---|---|---|
| `Linux-L0` | Linux实验1结束 | 三机身份、DHCP、课程镜像源、基础工具、VMware Tools和初始快照 | 实验2、4—6可直接恢复；实验3、7还需重建前序项目成果 |
| `Linux-L1` | Linux实验7结束 | `m1-project`、账号权限、软件源、服务日志和巡检成果 | 实验8—13起点 |
| `Linux-L2` | Linux实验13结束 | 三机静态网络、hosts、SSH密钥、firewalld和SELinux正确基线 | 实验14—19起点 |
| `Linux-L3` | Linux实验19结束 | Nginx、MySQL、MongoDB、Redis、Git、备份和巡检成果 | 实验20起点 |
| `Linux-L4` | Linux实验20结束 | Linux课程最终三机交付环境 | 第二门课程继承起点 |
| `VC-V0` | 虚拟化容器实验1结束 | `rocky-server`嵌套虚拟化资源和课程基线 | KVM阶段起点 |
| `VC-V1` | 虚拟化容器实验5结束 | KVM客户机、qcow2、网络、清单和恢复说明 | Docker阶段前回退点 |
| `VC-V2` | 虚拟化容器实验7结束 | Rocky与Ubuntu Docker基线、固定镜像和离线包 | 网络、卷与构建阶段起点 |
| `VC-V3` | 虚拟化容器实验10结束 | 应用镜像、Compose项目、卷备份和运行证据 | 实验11综合项目起点 |

检查点VM必须在正常关机后制作，并附一份文本清单，至少记录主机名、账号、IP方式、软件版本、检查点日期、磁盘文件位置和SHA256或文件大小。VMware快照用于快速回退；独立VM副本用于应对原虚拟机目录损坏或被还原，两者用途不同。

上表是教师维护的阶段基线，不代替学生的日常连续状态。如果学生VM无法存放在非还原位置，还需要按课程进度准备`Linux-W1`—`Linux-W8`、`VC-W1`—`VC-W8`周起点副本，或者在每次下课前把各组关机后的VM目录同步到持久共享位置。仅保存实验报告和命令记录，无法恢复下一次课所需的系统配置。

### 3. Linux实验1—7的状态关系

| 实验 | 可以从哪里开始 | 必须继承的对象 | 本实验新建且后续保留 |
|---|---|---|---|
| 实验1 | 干净宿主机 | 无 | 三台VM、课程镜像源、基础工具、`Linux-L0` |
| 实验2 | `Linux-L0` | `rocky-server`身份和sudo | `~/m1-project`及基础文件 |
| 实验3 | 实验2成果 | `~/m1-project/config/app.conf`及目录树 | 修改后配置、链接、归档与校验记录 |
| 实验4 | 推荐接续实验3；也可从`Linux-L0`独立完成 | 只要求管理账号和sudo | 项目账号、组、`/srv/course-share`、sudoers和权限证据 |
| 实验5 | 推荐接续实验4；也可从`Linux-L0`独立完成 | 可用课程软件源和sudo | 仓库备份、包管理证据，保留`jq`并恢复`tree` |
| 实验6 | 推荐接续实验5；也可从`Linux-L0`独立完成 | 主机名与用户名均为`rocky-server` | systemd脚本与日志证据；临时Unit验收后可清理 |
| 实验7 | 接续实验2—6成果 | 至少存在实验2创建的`~/m1-project` | 正式巡检报告，形成`Linux-L1` |

连续教学优先按1→2→3→4→5→6→7执行。发生机房还原时，实验3不能只恢复`Linux-L0`后创建一个空`app.conf`，实验7也不能创建空`m1-project`绕过依赖；应恢复最近周起点副本，或从`Linux-L0`重新完成实验2要求的正式成果。

### 4. 每个实验的恢复入口

实验开始时先执行手册中的“起点检查”。检查失败时只能选择以下一种路径：

1. 恢复手册指定的最近课程检查点；
2. 执行手册明确提供的准备步骤，重建缺失且可安全重建的对象；
3. 停止实验并由教师确认，不通过随意新建空文件、关闭防护或跳过验收掩盖缺失状态。

从前序实验继承的配置文件必须先使用`test`、`ls`、服务状态或功能请求证明存在；当前实验自身使用的日志、证据、备份和临时目录，应在第一次写入前使用`mkdir -p`创建。

## 四、模块环境准备

### 模块一：Linux基础运维（第1—3周）

```
□ VMware Workstation 17 Pro 已安装
□ Rocky Linux 9 minimal ISO 已就绪（放在 D:\ISO\ 或共享目录）
□ Ubuntu 22.04 Desktop amd64 ISO 已就绪，不使用live-server镜像
□ 两份ISO的SHA256已由教师校验并公布
□ 教室投影/屏幕共享方案确认（教师终端如何投影）
□ 学生机 VMware NAT网络已确认并记录实际网段、网关和DHCP范围
```

### 模块二：网络、远程管理与基础防护（第3—5周）

```
□ rocky-server、rocky-web、ubuntu-client三台VM已安装并建立初始快照
□ 三台VMware名称、主机名和主要用户名一致，教学密码均为123456
□ ubuntu-client图形桌面、Terminal和浏览器可用
□ 确认 VMware NAT 网络正常工作
□ 配置并验证清华源或阿里源；保留一份可回退的原始repo配置
□ 教师机保留课程所需RPM/DEB包或缓存，避免镜像站临时不可用
□ 教师准备好故障注入脚本（systemctl stop/防火墙规则/SELinux修改）
```

### 模块三：企业服务部署与综合运维（第6—8周）

```
□ rocky-web干净可用，实验14在该机安装Nginx
□ rocky-server干净可用，实验15—19在该机安装数据库、Git和巡检脚本
□ ubuntu-client图形客户端可用，名称解析、浏览器、curl、SSH和数据库客户端可安装
□ 确认清华源或阿里源可用；不把公共互联网持续可用作为课堂前提
□ Nginx、MySQL 8.4 LTS、MongoDB 8.0、Redis的统一仓库或离线包已验证
□ Git 远程仓库可用（或准备本地模拟方案）
□ 教师准备好故障注入方案：
  □ Nginx 停止
  □ 防火墙拦截
  □ SELinux 上下文修改
  □ MySQL 停止
  □ Redis 密码修改
```

### 《虚拟化容器技术》模块一：服务器虚拟化与云资源基础（24学时）

```
□ 学生宿主机 CPU 支持虚拟化（VT-x/AMD-V 在BIOS中开启）
□ 教师先抽测3-5台不同型号学生机能否开启VMware嵌套虚拟化
□ Windows中不会由其他虚拟化组件独占硬件虚拟化能力
□ rocky-server建议调整为4 vCPU、6—8GB内存、80GB以上磁盘
□ VMware为rocky-server启用嵌套虚拟化，系统内能看到vmx或svm
□ virt-host-validate、KVM内核模块和libvirt连接在抽测机中通过
□ KVM/QEMU/libvirt/virt-install工具包已进入统一仓库或离线目录
□ 教师轻量qcow2基础镜像已验证，带固定版本、SHA256和导入说明
□ 基础镜像为只读源，学生实验磁盘使用复制或差异镜像
□ libvirt默认NAT网络、DHCP、控制台和SSH访问均已测试
□ 同时运行Rocky宿主与1—2台轻量KVM客户机时资源可接受
□ 教师预建OpenStack平台可以从学生网络访问
□ OpenStack学生账号、Project、配额、镜像、Flavor、网络和安全组规则已准备
□ 每名学生能够创建、连接和删除至少一台轻量云主机
□ OpenStack不可用时的补做时段或统一远程环境已确定
```

### 《虚拟化容器技术》模块二：Docker容器化应用构建与交付（40学时）

```
□ rocky-server与ubuntu-client的Docker Engine、Compose插件仓库和离线安装包均已验证
□ Windows不要求Docker Desktop或WSL
□ rocky-server与ubuntu-client各有至少20GB剩余空间
□ 学校课程Registry已部署并可从两台Linux VM访问

□ 镜像清单包含镜像引用、摘要、架构、归档文件和SHA256
□ 所有课程镜像均已执行一次docker pull和一次docker load验证
□ U盘或共享目录离线包包含tar、SHA256SUMS、image-manifest.csv和README
□ Web、API、MySQL、Redis、toolbox与构建基础镜像均已准备
□ Dockerfile应用素材和Compose项目模板已在Rocky、Ubuntu分别运行
□ MySQL数据卷备份、模拟丢失与恢复流程已走通
□ 教师准备好故障注入方案：
  □ docker stop 某容器
  □ 错误镜像标签
  □ 端口冲突
  □ 网络名或服务名错误
  □ Volume或绑定挂载权限问题
  □ 环境变量和健康检查错误
□ 教师预建Kubernetes集群可访问
□ kubeconfig、context、学生Namespace、RBAC和资源配额已验证
□ Kubernetes能够拉取课程固定镜像
```
