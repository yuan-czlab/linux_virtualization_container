# 课程资料导航与版本说明

> 当前状态：《Linux操作系统》与《虚拟化容器技术》两门64学时课程均已建立正式结构
>
> 主线环境：Windows 10/11 + VMware Workstation + `rocky-server` + `rocky-web` + Ubuntu 22.04 Desktop `ubuntu-client`

## 一、授课顺序

```text
第一阶段：《Linux操作系统》
8周 × 8学时 = 64学时，20个实验
        ↓
第二阶段：《虚拟化容器技术》
8周 × 8学时 = 64学时，11个实验
```

箭头表示环境和能力的真实继承：第二门课程从`Linux-L4`开始，继续使用同一组`rocky-server`、`rocky-web`和`ubuntu-client`。KVM阶段在`rocky-server`内增加虚拟化层；Docker阶段继续使用该Rocky与原Ubuntu做跨发行版交付。除恢复检查点外，不重新安装干净系统来绕过Linux课程遗留状态。

两门课每周均按`2学时 + 4学时 + 2学时`三次到课组织。实验是完整项目，可以跨越多次课；课程进度表负责把实验映射到24次到课，不把实验手册机械拆分。

### 统一课堂闭环

教材是两门课程的知识主线，实验是知识的综合应用场景。每个2学时单元原则上形成一次完整闭环：

```text
实际问题导入
→ 教材必学知识（20—25分钟）
→ 自包含课堂练习（15—20分钟）
→ 练习检查与纠错（约5分钟）
→ 发布实验工单（约5分钟）
→ 学生独立或分组实验（约30分钟）
→ 验收、排障与记录（约10分钟）
```

4学时到课由两个闭环组成，可以继续同一实验的不同任务。安装、镜像导入、软件包下载等等待时间应穿插教材讲解、结果记录或小组互查，不把等待时间计算为有效实践时间。

三类资料的职责保持清楚：

| 资料 | 主要作用 | 不承担的内容 |
|---|---|---|
| 模块教材 | 按规定顺序解释知识、原理、命令，提供自包含练习和实验入口 | 不逐条代替项目实验手册 |
| 实验手册 | 提供情境、工单、环境起点、操作、验证、排障、保留和恢复要求 | 不重复大段百科式理论 |
| 课程进度表 | 规定每次到课讲到哪里、练到哪里、做到哪个实验任务 | 不取代教材和实验细节 |

教材练习使用独立且可安全清理的练习目录，必须在本练习内创建全部输入对象；项目实验可以继承前序成果，但必须明确写出状态依赖、起点检查和缺失时的恢复入口。

## 三、《Linux操作系统》资料链

1. 以`04-Linux操作系统-64学时实验项目索引.md`确定20个实验及学时边界。
2. 按`05-Linux操作系统-8周课程进度表.md`实施8周24次到课。
3. 使用`../labs/linux/`中的详细实验手册组织学生实践、验证、排障和提交。
4. 使用`../textbooks/01`至`03`讲授三个模块的原理与系统知识。
5. 使用`06-Linux操作系统-64学时知识图谱.xmind`完成课程导入和阶段复盘。

Linux课程使用三机基线：实验2—13主要操作`rocky-server`，实验14在`rocky-web`部署Nginx，实验15—19回到`rocky-server`部署MySQL、MongoDB和Redis，`ubuntu-client`全程承担图形化外部客户端和发行版对照。

2. 按`08-虚拟化容器技术-8周课程进度表.md`实施8周24次到课。

## 五、环境与资源规则

1. KVM为全员真实实验。学生在`rocky-server`中启用嵌套虚拟化并创建KVM客户机。
2. Docker在`rocky-server`和`ubuntu-client`中均完成安装，后续用同一镜像和项目验证跨发行版交付，不重复讲两套完整命令。
3. Windows不要求安装Docker Desktop，也不把WSL作为课程前置条件。
4. Docker镜像以学校课程Registry为主通道，以U盘或共享目录中的`docker save`归档为回退通道。
5. 每批镜像必须有固定标签、镜像摘要、适用架构、文件SHA-256、镜像清单和导入说明。
6. OpenStack和Kubernetes账号、配额、Namespace、课程镜像和清理规则由教师课前统一准备。
7. 密码、私钥、Token、kubeconfig和真实数据库转储不得进入公开提交。

## 六、大项目与旧资源

现行课程只保留`labs/linux/`和`labs/virtualization-container/`两套正式实验，不再设置独立的`projects`目录。

大项目并未取消：虚拟化容器实验10完成四服务Compose项目前置成果，实验11以8学时完成Kubernetes体验、跨Rocky/Ubuntu迁移、离线镜像交付、数据恢复、综合排障和个人答辩。实验11就是期末综合大项目，避免维护重复版本。

## 七、维护与交付检查

课程内容调整时，先修改相应课程的实验项目索引，再同步进度表、实验手册、模块教材和XMind。所有关键操作后应提供预期结果、判断标准或验收点；网络、SSH、防火墙、镜像、数据卷和平台资源变更应保留回退路径。

交付给教师或学生前检查：

- `course-design`编号应从00到10连续，共11个正式文件；
- 两份XMind均应能用XMind正常打开；
- Linux课程应为20个实验、64学时和24次到课；
- 虚拟化容器课程应为11个实验、64学时和24次到课；
- 项目中不应包含XMind生成程序、校验程序或导图导入源。
