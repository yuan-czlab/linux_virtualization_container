## 2.8.1 rsync解决什么问题

`scp`按指定对象传输文件；`rsync`会比较源和目标，只传输需要变化的内容，并可保留权限、时间等属性。

典型过程：

```text
比较源和目标
→ 找出新增或变化对象
→ 只传输必要内容
→ 更新目标目录
```

rsync不是自动保留所有历史版本的备份系统。如果源文件损坏或被删除，错误内容也可能在下一次同步中进入目标。

安装Rocky所需工具：

```bash
sudo dnf install -y rsync cronie
```

查看版本：

```bash
rsync --version
```

交互观察：[rsync增量同步、cron与恢复闭环动画](../../../animations/08-rsync-cron-backup-restore/index.html)。先完成“路径语义”和“增量与删除”。

## 2.8.2 源目录末尾斜杠

这是rsync最容易产生误解的地方。

```text
rsync -a source  backup/
```

含义：把`source`目录本身放进`backup/`，结果通常是`backup/source/...`。

```text
rsync -a source/ backup/
```

含义：只把`source/`里面的内容放进`backup/`。

不要靠记忆猜测，先用`--dry-run`观察目标结构。

## 2.8.3 路径语义练习

创建源目录：

```bash
mkdir -p ~/course-practice/m2/ch28/source/docs
```

创建文件：

```bash
touch ~/course-practice/m2/ch28/source/index.html
```

```bash
touch ~/course-practice/m2/ch28/source/docs/readme.txt
```

创建两个空目标：

```bash
mkdir -p ~/course-practice/m2/ch28/target-a
```

```bash
mkdir -p ~/course-practice/m2/ch28/target-b
```

不带末尾斜杠同步：

```bash
rsync -av ~/course-practice/m2/ch28/source ~/course-practice/m2/ch28/target-a/
```

带末尾斜杠同步：

```bash
rsync -av ~/course-practice/m2/ch28/source/ ~/course-practice/m2/ch28/target-b/
```

比较目录树：

```bash
find ~/course-practice/m2/ch28/target-a -maxdepth 3 -type f
```

```bash
find ~/course-practice/m2/ch28/target-b -maxdepth 3 -type f
```

如果希望目标直接包含`index.html`和`docs/`，应使用带末尾斜杠的源路径。

## 2.8.4 常用选项

| 选项 | 作用 |
|---|---|
| `-a` | 归档模式，递归并保留常用属性 |
| `-v` | 显示过程 |
| `-i` | 用代码显示对象为什么发生变化 |
| `-n`或`--dry-run` | 只预览，不实际修改 |
| `--delete` | 删除目标中源端已不存在的对象 |
| `-e ssh` | 远程同步时指定SSH通道 |
| `--exclude` | 排除匹配对象 |

`-a`不等于保存ACL、扩展属性和硬链接等所有信息。需要这些属性时，应根据需求增加`-A`、`-X`、`-H`并进行恢复测试。

## 2.8.5 观察增量同步

创建备份目录：

```bash
mkdir -p ~/course-practice/m2/ch28/backup
```

首次同步：

```bash
rsync -aiv ~/course-practice/m2/ch28/source/ ~/course-practice/m2/ch28/backup/
```

立即预览第二次同步：

```bash
rsync -aivn ~/course-practice/m2/ch28/source/ ~/course-practice/m2/ch28/backup/
```

没有变化时，不应再次列出需要传输的普通文件。

打开源文件：

```bash
vim ~/course-practice/m2/ch28/source/index.html
```

写入一行内容并保存。再次预览：

```bash
rsync -aivn ~/course-practice/m2/ch28/source/ ~/course-practice/m2/ch28/backup/
```

确认只有预期文件变化后，正式同步：

```bash
rsync -aiv ~/course-practice/m2/ch28/source/ ~/course-practice/m2/ch28/backup/
```

比较源和目标：

```bash
diff -qr ~/course-practice/m2/ch28/source ~/course-practice/m2/ch28/backup
```

`diff`没有输出通常表示普通文件内容和目录结构一致。

## 2.8.6 谨慎使用--delete

在目标中创建仅目标存在的文件：

```bash
touch ~/course-practice/m2/ch28/backup/obsolete.txt
```

先预览：

```bash
rsync -aivn --delete ~/course-practice/m2/ch28/source/ ~/course-practice/m2/ch28/backup/
```

输出应提示`obsolete.txt`将被删除，但文件仍然存在。

确认：

```bash
ls -l ~/course-practice/m2/ch28/backup/obsolete.txt
```

`--delete`会让目标更接近源的镜像，但也会传播误删。基础实验只做预览，不执行真实删除。

## 2.8.7 远程rsync

远程rsync通常通过SSH工作，而且两端都需要rsync程序。

在Ubuntu安装：

```bash
sudo apt install -y rsync
```

确认实验10的SSH别名：

```bash
ssh -G rocky-server | grep -E '^(hostname|user|identityfile) '
```

创建本地目标：

```bash
mkdir -p ~/course-practice/m2/remote-backup
```

预览从Rocky拉取网站目录：

```bash
rsync -aivn rocky-server:~/m1-project/web/ ~/course-practice/m2/remote-backup/
```

确认方向无误后同步：

```bash
rsync -aiv rocky-server:~/m1-project/web/ ~/course-practice/m2/remote-backup/
```

如果远端缺少rsync，SSH可能成功但同步仍会失败。

本章核心定时任务使用Rocky本地同步，避免把私钥口令和ssh-agent环境混入cron。远程定时备份作为拓展。

## 2.8.8 cron时间表达式

用户定时任务通过`crontab`管理。五个时间字段依次为：

```text
分钟 小时 日 月 星期 命令
```

示例：

```cron
30 18 * * * /home/rocky-server/m1-project/scripts/backup-web.sh
```

含义：每天18:30执行。

常见写法：

| 表达式 | 含义 |
|---|---|
| `* * * * *` | 每分钟 |
| `0 * * * *` | 每小时整点 |
| `30 18 * * *` | 每天18:30 |
| `0 2 * * 1` | 每周一02:00 |

星期字段在不同实现中对0和7的解释都可能表示星期日。课程中优先使用1～6表示周一至周六，并在实际系统验证。

## 2.8.9 cron不是交互式终端

cron任务通常具有：

- 更精简的`PATH`。
- 没有当前终端工作目录。
- 不自动加载交互式Shell配置。
- 没有当前终端的ssh-agent状态。
- 没有屏幕供程序询问口令。

因此定时脚本应使用绝对路径，主动创建目标目录，把标准输出和错误写入日志，并返回真实退出状态。

Rocky检查`crond`：

```bash
sudo systemctl enable --now crond
```

```bash
systemctl is-active crond
```

Ubuntu对应服务通常叫`cron`。

## 2.8.10 编写短备份脚本

自动执行需要一个固定入口，因此本节允许编写一个短脚本。每一行都来自前面已经手工验证的命令。

创建脚本目录：

```bash
mkdir -p ~/m1-project/scripts
```

用vim打开：

```bash
vim ~/m1-project/scripts/backup-web.sh
```

输入：

```text
#!/bin/bash
SOURCE=/home/rocky-server/m1-project/web/
TARGET=/home/rocky-server/backup-lab/web-current/
LOG=/home/rocky-server/backup-lab/logs/backup-web.log
mkdir -p "$TARGET" "$(dirname "$LOG")"
printf 'START %s\n' "$(date -Iseconds)" >> "$LOG"
/usr/bin/rsync -a --itemize-changes "$SOURCE" "$TARGET" >> "$LOG" 2>&1
rc=$?
printf 'END %s code=%s\n' "$(date -Iseconds)" "$rc" >> "$LOG"
exit "$rc"
```

逐行理解：

| 行 | 作用 |
|---|---|
| `#!` | 指定解释器 |
| `SOURCE/TARGET/LOG` | 固定绝对路径 |
| `mkdir` | 确保目标和日志目录存在 |
| 第一个`printf` | 记录开始时间 |
| `rsync` | 执行已验证的同步 |
| `rc=$?` | 立即保存rsync退出状态 |
| 第二个`printf` | 记录结束时间和结果 |
| `exit` | 把rsync结果返回给调用者 |

设置执行权限：

```bash
chmod 750 ~/m1-project/scripts/backup-web.sh
```

检查语法：

```bash
bash -n ~/m1-project/scripts/backup-web.sh
```

手工执行：

```bash
~/m1-project/scripts/backup-web.sh
```

查看日志：

```bash
tail -n 20 ~/backup-lab/logs/backup-web.log
```

只有手工运行成功，才能交给cron。

## 2.8.11 配置和验证crontab

编辑当前用户任务：

```bash
crontab -e
```

课堂验证时临时加入：

```cron
* * * * * /usr/bin/flock -n /tmp/backup-web.lock /home/rocky-server/m1-project/scripts/backup-web.sh
```

`flock -n`防止上一次任务未结束时重复启动。

保存后查看：

```bash
crontab -l
```

等待至少一次触发后查看备份日志：

```bash
tail -n 20 ~/backup-lab/logs/backup-web.log
```

查看crond日志：

```bash
sudo journalctl -u crond --since '5 minutes ago' --no-pager
```

验证完成后再次执行`crontab -e`，把每分钟任务改为合理频率：

```cron
30 18 * * * /usr/bin/flock -n /tmp/backup-web.lock /home/rocky-server/m1-project/scripts/backup-web.sh
```

## 2.8.12 隔离恢复

创建恢复目录：

```bash
mkdir -p ~/backup-lab/restore-test
```

把备份恢复到隔离目录：

```bash
rsync -av ~/backup-lab/web-current/ ~/backup-lab/restore-test/
```

比较源与恢复结果：

```bash
diff -qr ~/m1-project/web ~/backup-lab/restore-test
```

只有验证恢复结果正确后，才考虑恢复到业务目录。直接用未检查的备份覆盖源目录，可能扩大故障。
