## 学习目标

完成本章后，应能够：

1. 解释为什么“允许整个网段”和“只允许一台管理机”风险不同。
2. 读懂包含来源、协议、端口和动作的rich rule。
3. 说明普通端口规则可能使来源限制失效的原因。
4. 正确处理运行时、永久配置和reload。
5. 为防火墙变更同时设计验证和回滚命令。

## 2.10.1 为什么需要来源限制

普通端口规则：

```text
允许进入本zone的所有来源访问8080/tcp
```

来源限制规则：

```text
只允许ubuntu-client的IPv4地址访问8080/tcp
```

数据库、管理接口和内部API通常不应对整个网络开放。来源越窄，暴露面越小。

继续使用[firewalld区域、规则与安全变更动画](../../../animations/09-firewalld-zones-rules/index.html)的“运行时与永久”和“来源限制与回滚”。

## 2.10.2 rich rule结构

一个来源受限规则由若干部分组成：

```text
rule
family="ipv4"
source address="<允许的客户端IPv4>/32"
port port="8080" protocol="tcp"
accept
```

| 部分 | 作用 |
|---|---|
| `family="ipv4"` | 本规则匹配IPv4 |
| `source address=...` | 限定来源 |
| `port` | 指定目标端口和协议 |
| `accept` | 匹配后允许 |

使用`/32`表示只匹配一个IPv4地址。

假设Ubuntu实际地址是`192.168.200.30`，规则格式为：

```text
rule family="ipv4" source address="192.168.200.30/32" port port="8080" protocol="tcp" accept
```

实际实验必须使用实验8参数表中的真实地址。

## 2.10.3 为什么普通开放会绕过来源限制

如果同一个zone同时存在：

```text
ports: 8080/tcp
```

和：

```text
只允许ubuntu-client访问8080的rich rule
```

普通`8080/tcp`规则已经允许所有进入该zone的来源，因此rich rule没有实现“只有Ubuntu能访问”的预期边界。

配置来源限制前应检查：

```text
firewall-cmd --zone=<实际活动区域> --list-ports
```

```text
firewall-cmd --zone=<实际活动区域> --list-services
```

```text
firewall-cmd --zone=<实际活动区域> --list-rich-rules
```

必须同时考虑service、port和rich rule三类入口。

## 2.10.4 添加来源限制规则

运行时添加格式：

```text
sudo firewall-cmd --zone=<实际活动区域> --add-rich-rule='rule family="ipv4" source address="<Ubuntu实际IPv4>/32" port port="8080" protocol="tcp" accept'
```

查看：

```text
firewall-cmd --zone=<实际活动区域> --list-rich-rules
```

从`ubuntu-client`进行真实访问：

```bash
curl --connect-timeout 3 http://rocky-server:8080/
```

只有客户端访问成功且非授权来源失败，才能证明来源限制有效。只有一台客户端时，至少要保存规则、客户端地址和成功访问三类证据，并由小组交叉测试其他来源。

## 2.10.5 永久保存与reload

运行时验证成功后，使用完全相同的规则写入永久配置：

```text
sudo firewall-cmd --permanent --zone=<实际活动区域> --add-rich-rule='rule family="ipv4" source address="<Ubuntu实际IPv4>/32" port port="8080" protocol="tcp" accept'
```

重载：

```bash
sudo firewall-cmd --reload
```

分别查询运行时和永久规则：

```text
firewall-cmd --zone=<实际活动区域> --list-rich-rules
```

```text
firewall-cmd --permanent --zone=<实际活动区域> --list-rich-rules
```

reload后仍存在且客户端复测成功，才说明持久化闭环完成。

## 2.10.6 删除规则要求文本一致

删除rich rule时，需要提供与添加时一致的规则内容：

```text
sudo firewall-cmd --zone=<实际活动区域> --remove-rich-rule='rule family="ipv4" source address="<Ubuntu实际IPv4>/32" port port="8080" protocol="tcp" accept'
```

删除永久规则：

```text
sudo firewall-cmd --permanent --zone=<实际活动区域> --remove-rich-rule='rule family="ipv4" source address="<Ubuntu实际IPv4>/32" port port="8080" protocol="tcp" accept'
```

因此变更记录必须保存完整添加命令，不能只写“开放了8080”。

## 2.10.7 zone与NetworkManager连接

查看活动zone：

```bash
firewall-cmd --get-active-zones
```

查看NetworkManager连接：

```bash
nmcli connection show --active
```

查看连接配置中的zone字段：

```text
nmcli -g connection.zone connection show "<实际活动连接名>"
```

连接没有显式zone时，接口可能进入默认zone。修改zone归属会改变整块规则边界，基础实验只观察，不随意切换。

## 2.10.8 安全变更闭环

一次合格变更应包含：

```text
1. 业务需求：谁访问什么端口
2. 变更前证据：监听、zone、现有规则
3. 运行时规则：先验证
4. 客户端证据：允许来源成功
5. 非授权来源证据：其他来源失败
6. 永久规则：验证后保存
7. reload复测：证明持久
8. 回滚命令：删除同一规则
9. 回滚后复测：证明边界恢复
```

保存运行时规则：

```text
firewall-cmd --zone=<实际活动区域> --list-all > ~/m1-project/evidence/firewall-runtime-before.txt
```

保存永久规则：

```text
firewall-cmd --permanent --zone=<实际活动区域> --list-all > ~/m1-project/evidence/firewall-permanent-before.txt
```

## 2.10.9 端口转发认知

firewalld支持端口转发和地址伪装，但它会改变目标或源地址，需要同时考虑：

- 内核IP转发。
- 入站接口和出站接口。
- 目标主机回程路由。
- NAT后的日志和源地址。

本模块只要求理解，不执行端口转发。它将在网络或云计算课程结合完整拓扑学习。
