# 2.5 SSH远程管理

> 所属课程：《Linux操作系统》
> 所属模块：模块二 网络远程管理与基础防护
> 学习前置：2.1～2.4、实验8三机网络
> 对应实验：实验10“SSH远程管理与密钥认证”
> 学习方式：理解连接阶段 → 检查服务端 → 首次连接 → 读取日志 → 进入实验

## 学习目标

完成本章后，应能够：

1. 区分SSH客户端、`sshd`服务端和TCP 22端口。
2. 区分服务器主机密钥与用户认证密钥。
3. 安全完成首次连接和主机指纹核对。
4. 使用`ssh -v`、`ss`、`systemctl`和`journalctl`定位连接阶段。
5. 使用`sshd -t`和`sshd -T`检查配置语法与最终生效值。

## 2.5.1 SSH解决什么问题

SSH提供经过加密的远程登录、远程命令和文件传输通道。基本角色如下：

| 角色 | 本课程主机 | 主要程序 |
|---|---|---|
| 客户端 | `ubuntu-client` | `ssh`、`scp`、`sftp` |
| 服务端 | `rocky-server`、`rocky-web` | `sshd` |

一次SSH连接通常经历：

```text
解析服务器名称
→ 与服务器TCP 22端口建立连接
→ 协商算法
→ 客户端验证服务器主机身份
→ 服务器验证登录用户身份
→ 建立加密会话
```

`ping`成功只说明网络层可能可达，不能证明22端口监听、主机身份和用户认证都正常。

## 2.5.2 两类密钥不能混淆

| 密钥 | 回答的问题 | 常见位置 |
|---|---|---|
| 服务器主机密钥 | “连接的是不是原来的服务器” | 服务端`/etc/ssh/ssh_host_*` |
| 用户认证密钥 | “这个客户端用户是否有登录资格” | 客户端`~/.ssh/`和服务端`authorized_keys` |

服务器主机私钥保留在服务器，用户认证私钥保留在客户端。任何私钥都不应通过聊天、作业附件或公共Git仓库分发。

交互观察：[SSH信任、认证与文件传输动画](../../../animations/07-ssh-trust-auth-transfer/index.html)。先完成“主机身份”，明确`known_hosts`保存的不是用户登录密码。

## 2.5.3 安装并检查sshd

### Rocky Linux 9

安装服务端：

```bash
sudo dnf install -y openssh-server
```

设置开机启动并立即启动：

```bash
sudo systemctl enable --now sshd
```

查看运行状态：

```bash
systemctl status sshd --no-pager
```

检查22端口：

```bash
sudo ss -lntp | grep ':22 '
```

### Ubuntu 22.04对照

Ubuntu作为客户端时通常已经包含`ssh`。只有需要让Ubuntu接受远程登录时，才安装服务端：

```bash
sudo apt install -y openssh-server
```

Ubuntu的Unit通常叫`ssh.service`：

```bash
systemctl status ssh --no-pager
```

进程名称仍然是`sshd`。

## 2.5.4 检查firewalld中的SSH规则

在Rocky查看活动区域：

```bash
sudo firewall-cmd --get-active-zones
```

记录网卡所在区域，例如`public`。再查看该区域规则：

```text
sudo firewall-cmd --zone=<实际活动区域> --list-all
```

查询SSH服务：

```text
sudo firewall-cmd --zone=<实际活动区域> --query-service=ssh
```

若返回`no`，先从VMware控制台添加运行时规则：

```text
sudo firewall-cmd --zone=<实际活动区域> --add-service=ssh
```

从Ubuntu验证连接成功后，再考虑永久保存：

```text
sudo firewall-cmd --permanent --zone=<实际活动区域> --add-service=ssh
```

本章不要求关闭firewalld，也不把区域名称固定假设为`public`。

## 2.5.5 首次连接与主机指纹

### 在服务端显示可信指纹

在`rocky-server`的VMware控制台执行：

```bash
sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

在`rocky-web`控制台执行同一命令，并分别记录两台服务器的SHA256指纹。

### 在客户端测试TCP端口

在`ubuntu-client`执行：

```bash
nc -vz -w 3 rocky-server 22
```

端口成功后再尝试SSH：

```bash
ssh rocky-server@rocky-server
```

命令中：

- `@`前的`rocky-server`是服务端用户名。
- `@`后的`rocky-server`是由实验8解析的主机名。

首次连接会显示主机密钥指纹。只有与VMware控制台中的可信指纹一致，才能输入`yes`。

随后输入实验环境密码，登录成功后确认远端身份：

```bash
whoami
```

```bash
hostnamectl --static
```

退出远程会话：

```bash
exit
```

连接`rocky-web`：

```bash
ssh rocky-web@rocky-web
```

## 2.5.6 known_hosts记录服务器身份

在Ubuntu查看已经保存的主机记录：

```bash
ssh-keygen -F rocky-server
```

```bash
ssh-keygen -F rocky-web
```

`known_hosts`用于发现“同一个名称对应的主机密钥发生变化”。出现`REMOTE HOST IDENTIFICATION HAS CHANGED`时，可能原因包括：

- 服务器重新安装并生成了新主机密钥。
- 名称或IP被分配给另一台主机。
- 连接被劫持或遭遇中间人攻击。

不能看到警告就直接删除记录。应先在可信控制台核对新指纹。确认是合法重装后，才删除旧记录：

```bash
ssh-keygen -R rocky-server
```

删除后再次连接，仍要重新核对指纹。

## 2.5.7 使用-v观察连接阶段

在Ubuntu执行：

```bash
ssh -v rocky-server@rocky-server
```

重点观察：

1. 读取了哪些客户端配置。
2. 名称最终解析成哪个IP。
3. 正在连接哪个端口。
4. 服务器提供了哪种主机密钥。
5. 客户端尝试了哪些用户认证方式。
6. 失败发生在连接、主机验证还是用户认证阶段。

`-vv`和`-vvv`提供更多信息，但输出更长。基础排障先从`-v`开始。

## 2.5.8 检查服务端有效配置

检查语法：

```bash
sudo sshd -t
```

命令没有输出且退出状态为0，通常表示语法通过。紧接着查看退出状态：

```bash
echo $?
```

查看最终生效配置：

```bash
sudo sshd -T | grep -E '^(port|listenaddress|permitrootlogin|passwordauthentication|pubkeyauthentication|maxauthtries) '
```

`sshd -T`会合并主配置和配置片段，结果比只搜索某一行配置文件更可靠。

常见位置：

| 路径 | 作用 |
|---|---|
| `/etc/ssh/sshd_config` | 主配置 |
| `/etc/ssh/sshd_config.d/*.conf` | 配置片段 |
| `/etc/ssh/ssh_host_*` | 服务器主机密钥 |

不要在密钥登录尚未验证时关闭密码认证。SSH安全修改必须保留一个已登录会话，并用第二个会话复测。

## 2.5.9 SSH日志与排障

Rocky查看最近日志：

```bash
sudo journalctl -u sshd -n 50 --no-pager
```

查看最近10分钟：

```bash
sudo journalctl -u sshd --since '10 minutes ago' --no-pager
```

Ubuntu服务端对照：

```bash
sudo journalctl -u ssh -n 50 --no-pager
```

推荐排障顺序：

```text
getent确认名称
→ ip route get确认路径
→ nc确认TCP 22
→ systemctl确认sshd
→ ss确认监听
→ firewalld确认规则
→ ssh -v确认客户端阶段
→ journalctl确认服务端原因
```

## 本章练习：SSH只读证据表

在`rocky-server`逐条完成：

| 项目 | 命令 | 实际结果 |
|---|---|---|
| 服务状态 | `systemctl is-active sshd` | |
| 开机启动 | `systemctl is-enabled sshd` | |
| 配置语法 | `sudo sshd -t` | |
| 有效配置 | `sudo sshd -T` | |
| 22端口 | `sudo ss -lntp` | |
| 最近日志 | `sudo journalctl -u sshd -n 10 --no-pager` | |

在`ubuntu-client`完成：

1. 使用`nc`证明22端口能够建立TCP连接。
2. 核对主机指纹后使用密码登录。
3. 进入远端后执行`whoami`和`hostnamectl --static`。
4. 退出后使用`ssh-keygen -F`查看已保存记录。
5. 使用`ssh -v`指出连接、主机验证和用户认证阶段。

本章只读检查服务端配置，不关闭密码认证。真实配置变更与双会话验证在实验10完成。
