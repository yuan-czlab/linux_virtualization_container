# 2.11 SELinux与主机基础防护

> 所属课程：《Linux操作系统》
> 所属模块：模块二 网络远程管理与基础防护
> 学习前置：文件权限、systemd、SSH和firewalld
> 对应实验：实验12“firewalld与SELinux基础防护”
> 学习方式：区分DAC与MAC → 读取模式和标签 → 理解持久标签 → 按日志排障

## 学习目标

完成本章后，应能够：

1. 区分传统文件权限DAC与SELinux强制访问控制MAC。
2. 说明Enforcing、Permissive和Disabled的区别。
3. 读取进程和文件的SELinux安全上下文。
4. 区分`chcon`、`restorecon`和`semanage fcontext`。
5. 使用AVC日志判断SELinux是否参与拒绝。
6. 在Enforcing模式下选择标签、布尔值或配置修复，而不是关闭SELinux。

## 2.11.1 DAC与MAC是两次判定

Linux传统权限由所有者、所属组、rwx和ACL等组成，称为自主访问控制DAC。SELinux根据安全上下文和策略再次判断，属于强制访问控制MAC。

```text
进程发起访问
→ DAC检查用户、组、rwx和ACL
→ SELinux检查源类型、目标类型、对象类别和策略
→ 两层都允许，访问才成功
```

因此：

- `chmod 777`不能解决所有访问问题。
- SELinux允许也不能绕过普通文件权限。
- 网络不通通常先检查路由、监听和firewalld，不能一开始就怀疑SELinux。

交互观察：[SELinux双重判定、上下文与AVC排障动画](../../../animations/10-selinux-dac-context-avc/index.html)。

## 2.11.2 SELinux运行模式

查看模式：

```bash
getenforce
```

查看详细状态：

```bash
sestatus
```

| 模式 | 是否执行策略 | 是否记录拒绝 |
|---|---|---|
| Enforcing | 是 | 是 |
| Permissive | 否，只记录 | 是 |
| Disabled | 不加载完整策略 | 无正常策略判定 |

课程基线是`Enforcing`。Permissive可以用于受控诊断，但不是最终修复；Disabled会失去重要保护，也可能需要重启才能完整切换。

临时切换命令仅作认识：

```text
sudo setenforce 0
```

```text
sudo setenforce 1
```

实验12不通过切换Permissive完成验收。

## 2.11.3 安全上下文

典型格式：

```text
user:role:type:level
```

应用排障最常关注`type`。

查看文件标签：

```bash
ls -lZ /var/www
```

查看进程标签：

```bash
ps -eZ | head
```

查看SSH授权文件标签：

```bash
ls -lZ ~/.ssh/authorized_keys
```

常见类型示例：

| 对象 | 常见类型 |
|---|---|
| 用户家目录文件 | `user_home_t` |
| SSH用户配置 | `ssh_home_t` |
| Web只读内容 | `httpd_sys_content_t` |
| httpd进程 | `httpd_t` |

实际类型应通过当前系统策略查询，不能只凭表格硬记。

## 2.11.4 默认标签从哪里来

`matchpathcon`可以查询策略认为某路径应使用的默认标签：

```bash
matchpathcon ~/.ssh/authorized_keys
```

比较当前标签：

```bash
ls -lZ ~/.ssh/authorized_keys
```

如果当前标签与策略默认值不同，`restorecon`可以恢复：

```bash
restorecon -v ~/.ssh/authorized_keys
```

## 2.11.5 chcon、restorecon和semanage fcontext

| 工具 | 作用 | 是否建立持久路径规则 |
|---|---|---|
| `chcon` | 直接修改当前对象标签 | 否 |
| `restorecon` | 按策略数据库恢复默认标签 | 使用已有规则 |
| `semanage fcontext` | 新增或修改路径到类型的持久映射 | 是 |

`chcon`适合制造实验故障或临时验证，后续`restorecon`、重新标记或文件复制可能覆盖它。

查看系统是否有`semanage`：

```bash
command -v semanage
```

Rocky缺少时安装：

```bash
sudo dnf install -y policycoreutils-python-utils
```

为自定义Web目录设计持久标签：

```text
sudo semanage fcontext -a -t httpd_sys_content_t '/srv/selinux-lab(/.*)?'
```

应用：

```bash
sudo restorecon -RFv /srv/selinux-lab
```

如果规则已经存在，`-a`会报错，应先查询，再根据变更需求使用`-m`修改，不能用`2>/dev/null ||`隐藏原因。

查询规则：

```bash
sudo semanage fcontext -l | grep '/srv/selinux-lab'
```

## 2.11.6 SELinux布尔值

布尔值用于开启或关闭策略预先设计的可选能力。

查看httpd相关布尔值：

```bash
getsebool -a | grep '^httpd_'
```

查看单项：

```bash
getsebool httpd_can_network_connect
```

临时修改格式：

```text
sudo setsebool httpd_can_network_connect on
```

永久修改需要`-P`：

```text
sudo setsebool -P httpd_can_network_connect on
```

只有业务确实需要且日志证据支持时才开启。不能为方便一次打开所有httpd布尔值。

## 2.11.7 AVC日志与排障

SELinux拒绝通常记录为AVC。

查看最近日志：

```bash
sudo ausearch -m AVC,USER_AVC -ts recent
```

从journal搜索：

```bash
sudo journalctl --since '10 minutes ago' | grep -i avc
```

基本排障顺序：

```text
确认实际失败现象
→ 检查DAC权限和所有者
→ 确认SELinux为Enforcing
→ 查看进程和文件当前标签
→ 查询默认标签和持久规则
→ 查找与失败时间一致的AVC
→ 判断应修复标签、布尔值还是应用配置
→ 保持Enforcing并复测
```

`audit2why`可辅助解释拒绝，但自动生成允许策略不是基础实验的首选修复。先判断文件是否放错位置、标签是否错误或已有布尔值能否满足需求。

## 2.11.8 firewalld与SELinux不要混为一谈

| 层次 | 典型工具 | 主要问题 |
|---|---|---|
| 进程状态 | `systemctl` | 服务是否运行 |
| Socket | `ss` | 是否监听正确地址和端口 |
| 网络访问 | `firewall-cmd` | 数据包是否允许进入 |
| DAC | `ls -l`、`namei -l` | 用户和权限是否允许 |
| SELinux | `ls -Z`、`ausearch` | 类型与策略是否允许 |

开放防火墙不能修复错误文件标签；修复SELinux标签也不能创建端口监听。

## 2.11.9 Ubuntu安全模块对照

Ubuntu默认更常使用AppArmor：

```bash
sudo aa-status
```

AppArmor与SELinux实现方式不同，但都属于额外的强制访问控制层。本课程以Rocky SELinux为主，不要求在Ubuntu复制相同命令。

## 2.11.10 主机基础防护清单

- 保持系统和安全更新。
- 使用普通管理员账号和`sudo`。
- SSH禁止直接root登录。
- 验证密钥认证后再考虑关闭密码认证。
- firewalld只开放必要服务、端口和来源。
- SELinux保持Enforcing。
- 数据库和缓存默认绑定回环地址或受限地址。
- 修改前备份，修改后检查语法、日志和真实访问。
