# 2.6 SSH密钥认证

> 所属课程：《Linux操作系统》
> 所属模块：模块二 网络远程管理与基础防护
> 学习前置：2.5 SSH远程管理
> 对应实验：实验10“SSH远程管理与密钥认证”
> 学习方式：理解签名认证 → 生成课程密钥 → 分发公钥 → 强制验证 → 进入实验

## 学习目标

完成本章后，应能够：

1. 说明公钥认证过程中私钥、公钥和`authorized_keys`的位置。
2. 在Ubuntu客户端生成独立的Ed25519课程密钥。
3. 使用`ssh-copy-id`把公钥部署到两台Rocky服务器。
4. 使用明确选项证明登录成功来自指定密钥。
5. 检查并修复`~/.ssh`、私钥和`authorized_keys`权限。
6. 说明关闭密码认证前必须完成的安全验证。

## 2.6.1 公钥认证不是传送私钥

公钥认证的核心过程：

```text
客户端保存私钥和公钥
→ 服务端authorized_keys保存允许登录的公钥
→ 服务端发送本次认证相关数据
→ 客户端使用私钥完成签名
→ 服务端使用公钥验证签名
→ 私钥始终留在客户端
```

文件位置：

| 文件 | 所在主机 | 是否保密 | 作用 |
|---|---|---|---|
| `linux-course-ed25519` | `ubuntu-client` | 必须保密 | 用户私钥 |
| `linux-course-ed25519.pub` | `ubuntu-client` | 可公开 | 用户公钥 |
| `authorized_keys` | 两台Rocky | 内容为允许登录的公钥 | 登录授权清单 |

公钥不是密码。把公钥复制到服务器，等于授予对应私钥登录该用户的资格。

继续使用[SSH信任、认证与文件传输动画](../../../animations/07-ssh-trust-auth-transfer/index.html)的“用户认证”，重点确认认证过程中不会把私钥发送给服务器。

## 2.6.2 为什么优先使用Ed25519

Ed25519密钥短、速度快，并具有现代安全设计，适合作为本课程默认类型。只有兼容旧设备或特定合规要求时，才考虑其他算法。

`ssh-keygen`中的常见参数：

| 参数 | 含义 |
|---|---|
| `-t ed25519` | 选择Ed25519算法 |
| `-f PATH` | 指定保存路径 |
| `-C TEXT` | 添加便于识别的注释 |
| `-a 64` | 增加私钥口令派生轮次，提高口令猜测成本 |

密钥文件名应体现用途，不要在课程中覆盖个人已有的`id_ed25519`。

## 2.6.3 在ubuntu-client生成课程密钥

先确认身份：

```bash
hostnamectl --static
```

预期是`ubuntu-client`。

查看已有SSH目录：

```bash
ls -la ~/.ssh
```

目录不存在时创建：

```bash
mkdir -p ~/.ssh
```

设置目录权限：

```bash
chmod 700 ~/.ssh
```

检查课程密钥是否已经存在：

```bash
ls -l ~/.ssh/linux-course-ed25519
```

若提示文件不存在，生成新密钥：

```bash
ssh-keygen -t ed25519 -a 64 -f ~/.ssh/linux-course-ed25519 -C 'linux-course@ubuntu-client'
```

命令会询问私钥口令：

- 正式环境建议设置高强度口令。
- 课堂应记录自己选择的口令，不在文档中统一公布。
- 已存在同名文件时不要确认覆盖，应先查明来源。

查看两个文件：

```bash
ls -l ~/.ssh/linux-course-ed25519*
```

私钥通常为600，公钥可以为644。显示公钥指纹：

```bash
ssh-keygen -lf ~/.ssh/linux-course-ed25519.pub
```

只查看公钥内容：

```bash
cat ~/.ssh/linux-course-ed25519.pub
```

不要使用`cat`展示私钥。

## 2.6.4 使用ssh-copy-id分发公钥

先确认密码登录仍然可用：

```bash
ssh rocky-server@rocky-server
```

退出：

```bash
exit
```

把公钥部署到`rocky-server`：

```bash
ssh-copy-id -i ~/.ssh/linux-course-ed25519.pub rocky-server@rocky-server
```

输入的是服务端用户`rocky-server`的密码，不是私钥口令。

部署到`rocky-web`：

```bash
ssh-copy-id -i ~/.ssh/linux-course-ed25519.pub rocky-web@rocky-web
```

`ssh-copy-id`会把公钥追加到远端用户的`~/.ssh/authorized_keys`，不会把私钥复制到服务器。

## 2.6.5 在服务端检查授权文件

通过VMware控制台或SSH进入`rocky-server`。

检查目录：

```bash
ls -ld ~/.ssh
```

检查授权文件：

```bash
ls -l ~/.ssh/authorized_keys
```

查看最后一条公钥：

```bash
tail -n 1 ~/.ssh/authorized_keys
```

检查所有者和数字权限：

```bash
stat -c '%A %a %U:%G %n' ~/.ssh ~/.ssh/authorized_keys
```

推荐值：

| 对象 | 推荐权限 | 所有者 |
|---|---:|---|
| 用户家目录 | 不允许其他用户写入 | 登录用户 |
| `~/.ssh` | 700 | 登录用户 |
| `authorized_keys` | 600 | 登录用户 |
| 客户端私钥 | 600 | 客户端用户 |

权限错误时，在对应用户自己的会话中修复目录：

```bash
chmod 700 ~/.ssh
```

修复授权文件：

```bash
chmod 600 ~/.ssh/authorized_keys
```

不要对整个家目录盲目执行递归`chmod`。

## 2.6.6 证明登录使用了指定密钥

回到`ubuntu-client`。

测试`rocky-server`：

```bash
ssh -o PasswordAuthentication=no -o IdentitiesOnly=yes -i ~/.ssh/linux-course-ed25519 rocky-server@rocky-server
```

选项含义：

| 选项 | 作用 |
|---|---|
| `PasswordAuthentication=no` | 本次连接不回退到密码 |
| `IdentitiesOnly=yes` | 只使用明确指定的身份文件 |
| `-i FILE` | 指定私钥 |

登录后确认：

```bash
whoami
```

退出：

```bash
exit
```

测试`rocky-web`：

```bash
ssh -o PasswordAuthentication=no -o IdentitiesOnly=yes -i ~/.ssh/linux-course-ed25519 rocky-web@rocky-web
```

这两次成功才能证明指定密钥已经部署到对应账号。

## 2.6.7 使用ssh-agent减少重复输入

设置了私钥口令时，可以让`ssh-agent`在当前登录会话中临时保存解锁后的使用能力。

启动Agent：

```bash
eval "$(ssh-agent -s)"
```

加入课程私钥：

```bash
ssh-add ~/.ssh/linux-course-ed25519
```

查看已经加载的密钥：

```bash
ssh-add -l
```

再次登录：

```bash
ssh -i ~/.ssh/linux-course-ed25519 rocky-server@rocky-server
```

`ssh-agent`不等于把私钥上传到服务器，但Agent转发可能让远端间接使用本地身份。本课程基础实验不启用`ForwardAgent yes`。

## 2.6.8 密钥认证故障排查

客户端详细观察：

```bash
ssh -v -o IdentitiesOnly=yes -i ~/.ssh/linux-course-ed25519 rocky-server@rocky-server
```

服务端查看日志：

```bash
sudo journalctl -u sshd --since '10 minutes ago' --no-pager
```

常见问题：

| 现象 | 检查方向 |
|---|---|
| 客户端没有尝试课程私钥 | `-i`路径、`IdentitiesOnly`、客户端配置 |
| `UNPROTECTED PRIVATE KEY FILE` | 客户端私钥权限过宽 |
| `Permission denied (publickey)` | 公钥是否部署到正确远端用户 |
| `bad ownership or modes` | 家目录、`.ssh`和`authorized_keys`权限 |
| Rocky文件权限正确仍失败 | SELinux上下文和服务端日志 |

Rocky检查SELinux上下文：

```bash
ls -laZ ~/.ssh
```

确认文件位置正确后恢复默认上下文：

```bash
restorecon -RFv ~/.ssh
```

普通用户通常可以恢复自己家目录中允许管理的上下文；若权限不足，再使用`sudo`。

## 2.6.9 何时才能关闭密码认证

关闭密码认证前必须满足：

1. 至少一个普通管理员账号的密钥登录已成功。
2. 已保留一个现有管理会话。
3. VMware控制台或其他带外入口可用。
4. 新配置已经通过`sshd -t`。
5. 使用第二个新会话完成无密码回退测试。

安全顺序：

```text
部署公钥
→ 强制只用指定密钥测试
→ 保留旧会话
→ 写配置片段
→ sshd -t
→ reload
→ 打开第二个新会话复测
→ 查看sshd -T和日志
```

教材章节不直接关闭密码认证，实验10将在明确回退条件下完成配置验证。
