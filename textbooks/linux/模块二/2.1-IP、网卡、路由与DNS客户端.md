## 2.1.1 一次网络访问需要哪些条件

Linux访问另一个地址时，会依次使用多个对象：

```text
应用给出目标名称或IP
→ 名称通过hosts或DNS转换为IP
→ 路由表选择出口网卡、源地址和下一跳
→ 网卡必须处于UP状态并拥有正确地址与前缀
→ 主机解析下一跳MAC地址
→ 数据包离开主机
```

| 对象 | 解决的问题 | 常用检查命令 |
|---|---|---|
| 网卡 | 从哪个接口收发数据 | `ip link`、`nmcli device` |
| IP地址和前缀 | 本机身份以及直连网络范围 | `ip address` |
| 路由 | 目标从哪里发送 | `ip route`、`ip route get` |
| 默认网关 | 非直连目标交给谁转发 | `ip route` |
| DNS客户端 | 名称如何转换为地址 | `getent hosts`、`resolvectl` |
| 邻居表 | 下一跳IP对应哪个MAC地址 | `ip neigh` |

交互观察：打开[Linux网络配置、路由与DNS动画](../../../animations/05-linux-network-routing-dns/index.html)，完成“设备与连接”和“路由与网关”。先预测出口、下一跳和源地址，再用真实命令验证。

“有IP”不等于“网络正常”。地址重复、前缀错误、默认路由缺失、DNS不可用或服务端防护都可能导致访问失败。

## 2.1.2 使用ip逐层查看网络状态

先观察接口是否为UP：

```bash
ip -br link
```

再观察每个接口的地址和前缀：

```bash
ip -br address
```

查看路由表：

```bash
ip route
```

从输出中填写本机参数：

| 参数 | 实际值 |
|---|---|
| 实验网卡名 |  |
| IPv4地址/前缀 |  |
| 默认网关 |  |
| 默认路由出口接口 |  |

不要照抄教材中的`ens33`或`192.168.200.2`。它们只是示例，真实值取决于VMware的VMnet8设置。

`ip route get`不会发送数据包，而是询问内核“如果访问这个目标，准备怎样发送”。先选择同学或教师提供的实际目标地址，再按下面格式替换：

```text
ip route get 目标IPv4地址
```

示例结果：

```text
192.168.200.20 dev ens33 src 192.168.200.10
```

它表示目标属于直连网段，准备从`ens33`发送，并使用`192.168.200.10`作为源地址。

查看当前邻居表：

```bash
ip neigh
```

邻居表为空不一定是故障。主机尚未与同网段目标通信，或记录已经过期时，都可能暂时没有条目。

## 2.1.3 临时配置与永久配置

`ip address add`直接修改内核运行状态，重新启动或重新激活连接后通常会消失。它适合临时测试，不适合作为课程最终配置。

命令格式如下，先理解各参数，不在教材短练习中直接执行：

```text
sudo ip address add 辅助地址/前缀 dev 实际网卡名
```

删除临时地址的格式：

```text
sudo ip address del 辅助地址/前缀 dev 实际网卡名
```

临时添加地址前必须确认：

1. 操作的是实验网卡。
2. 地址属于VMnet8实验网段。
3. 地址没有被其他主机使用。
4. 不会删除当前SSH管理地址。
5. 已保留VMware控制台作为恢复入口。

实验8将使用NetworkManager创建永久静态连接，不要求在本节先修改网络。

## 2.1.4 NetworkManager中的device与connection

NetworkManager管理两类不同对象：

```text
device：实际网卡，例如ens33
connection：一组可保存和反复激活的网络配置
```

一张网卡可以存在多个connection，但某一时刻通常只有一个主要连接处于活动状态。连接名不一定等于网卡名。

查看设备状态：

```bash
nmcli device status
```

查看所有连接配置：

```bash
nmcli connection show
```

只查看当前活动连接：

```bash
nmcli connection show --active
```

查看设备的详细IPv4信息：

```bash
nmcli -f GENERAL,IP4 device show
```

根据输出填写：

| 主机 | device | 活动connection | 当前IPv4/前缀 | 网关 | DNS |
|---|---|---|---|---|---|
| rocky-server |  |  |  |  |  |
| rocky-web |  |  |  |  |  |
| ubuntu-client |  |  |  |  |  |

## 2.1.5 静态连接需要哪些参数

创建静态连接前至少需要：

- 实际网卡名；
- 不与其他主机冲突的IPv4地址和前缀；
- VMnet8实际网关；
- 可用DNS服务器；
- 新连接名；
- 原连接名和回滚方法。

三台虚拟机必须使用同一VMnet8网段，但主机地址不能重复。课程建议在实验8开始时由教师公布地址表，而不是让学生自行猜测。

`nmcli`创建静态连接的基本结构如下。这是命令模板，中文部分必须替换，不能原样执行：

```text
sudo nmcli connection add type ethernet con-name 新连接名 ifname 实际网卡名 ipv4.method manual ipv4.addresses 实际地址/前缀 ipv4.gateway 实际网关 ipv4.dns 实际DNS
```

激活连接的格式：

```text
sudo nmcli connection up 新连接名
```

网络修改必须在VMware控制台中进行。激活后按以下顺序逐条验证。

查看地址：

```bash
ip -br address
```

查看路由：

```bash
ip route
```

查看NetworkManager活动连接：

```bash
nmcli connection show --active
```

查看DNS解析是否可用：

```bash
getent hosts mirrors.aliyun.com
```

再根据`ip route`中记录的实际网关执行：

```text
ping -c 3 实际网关IPv4地址
```

如果地址或网关错误，应在控制台停用新连接并重新激活原连接。命令格式为：

```text
sudo nmcli connection down 新连接名
sudo nmcli connection up 原连接名
```

这两条是回滚顺序，不是要求一次粘贴运行的脚本。实验8会使用真实名称逐条操作。

## 2.1.6 DNS客户端配置

Rocky中的`/etc/resolv.conf`通常由NetworkManager生成。先查看它是不是链接：

```bash
ls -l /etc/resolv.conf
```

查看当前内容：

```bash
cat /etc/resolv.conf
```

查看NetworkManager报告的DNS：

```bash
nmcli -f IP4.DNS,IP4.DOMAIN device show
```

验证名称解析时使用系统真实解析路径：

```bash
getent hosts mirrors.aliyun.com
```

直接覆盖`/etc/resolv.conf`可能在重新联网后失效。永久DNS应写入connection。命令模板如下：

```text
sudo nmcli connection modify 实际连接名 ipv4.ignore-auto-dns yes ipv4.dns "DNS1 DNS2"
```

修改后需要重新激活连接，并再次使用`nmcli device show`和`getent hosts`验证。实验8会安排一次错误DNS的“制造—观察—恢复—复测”。

```bash

```



