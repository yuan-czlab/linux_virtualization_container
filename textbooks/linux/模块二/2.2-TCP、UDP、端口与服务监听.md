## 学习目标

完成本章后，应能够：

1. 说明IP地址、协议、端口、Socket和进程之间的关系。
2. 比较TCP与UDP在连接、可靠性和排障方法上的区别。
3. 使用`ss`找到监听地址、端口和所属进程。

5. 使用`nc`验证TCP连接，并区分成功、拒绝和超时。

## 2.2.1 从IP地址到进程

IP地址只能把数据送到一台主机。主机上可能同时运行SSH、Web和数据库等多个服务，还需要端口把数据交给正确的进程。

```text
客户端进程
→ 目标IP：找到目标主机
→ 传输层协议：选择TCP或UDP
→ 目标端口：找到目标服务
→ Socket：操作系统维护的通信端点
→ 服务进程：处理请求
```

一个常见Socket可以表示为：

```text
协议 + 本地地址 + 本地端口
```

例如`TCP 0.0.0.0:22`表示某个进程正在所有本机IPv4接口的22端口上等待TCP连接。

端口号的范围是0～65535。常见分类如下：

| 范围 | 常见含义 |
|---|---|
| 0～1023 | 知名端口，Linux普通用户通常不能直接监听 |
| 1024～49151 | 注册端口，许多应用默认使用 |
| 49152～65535 | 常用于客户端临时端口 |

端口不是软件永久占有的编号。只有进程运行并成功绑定后，系统中才存在对应监听。

同一个数字可以分别出现在TCP和UDP中。例如DNS常同时使用UDP 53和TCP 53，它们是两个不同的Socket。

## 2.2.2 TCP与UDP

| 比较项 | TCP | UDP |
|---|---|---|
| 建立连接 | 通信前进行握手 | 不建立连接 |
| 可靠性 | 提供序号、确认和重传 | 协议本身不保证送达 |
| 数据形式 | 连续字节流 | 一个个独立数据报 |
| 常见应用 | SSH、HTTP、HTTPS、数据库 | DNS常规查询、NTP、实时音视频 |
| 主要证据 | 监听、连接状态、握手、应用响应 | 监听、应用响应、抓包 |

### TCP三次握手

TCP建立连接时，双方要确认彼此的发送和接收能力：

```text
客户端 → SYN → 服务端
客户端 ← SYN + ACK ← 服务端
客户端 → ACK → 服务端
```

握手成功只能证明TCP连接建立，不能证明登录认证、HTTP请求或数据库查询一定成功。

### UDP没有“连接成功”证据

UDP不进行TCP三次握手。使用`nc -u`发送数据时，即使没有应用响应，也可能没有明确报错。因此UDP排障必须结合真实协议请求、服务日志或抓包，不能只看`nc`的一句话。

## 2.2.3 使用ss查看Socket

`ss`是Linux中查看Socket的主要工具。

只看TCP监听：

```bash
ss -lnt
```

只看UDP监听：

```bash
ss -lnu
```

同时查看TCP、UDP和进程：

```bash
sudo ss -lntup
```

查看已经建立的TCP连接：

```bash
ss -tan state established
```

查看处于`TIME-WAIT`的TCP连接：

```bash
ss -tan state time-wait
```

常用选项：

| 选项 | 含义 |
|---|---|
| `-l` | 只显示监听Socket |
| `-n` | 直接显示数字，不把端口转换成服务名 |
| `-t` | 显示TCP |
| `-u` | 显示UDP |
| `-p` | 显示所属进程，通常需要管理员权限 |
| `-a` | 显示监听和非监听Socket |

观察`ss -lnt`的典型结果：

```text
State  Recv-Q Send-Q Local Address:Port Peer Address:Port
LISTEN 0      128          0.0.0.0:22        0.0.0.0:*
```

- `State`为`LISTEN`，表示正在等待TCP连接。
- `Local Address:Port`是服务绑定的本地地址和端口。
- `Peer Address:Port`中的`*`表示监听状态还没有固定对端。

## 2.2.4 监听地址决定访问范围

同一个端口绑定到不同地址，可访问范围不同。

| 监听地址 | 含义 |
|---|---|
| `127.0.0.1:8080` | 只有本机IPv4回环地址可以访问 |
| `某个网卡IP:8080` | 只有发往该本机地址的请求可以进入 |
| `0.0.0.0:8080` | 所有本机IPv4接口都可以接收 |
| `[::1]:8080` | 只有本机IPv6回环地址可以访问 |
| `[::]:8080` | 所有本机IPv6接口；是否兼容IPv4取决于系统配置 |

`0.0.0.0`是监听时使用的通配地址，不是客户端正常访问时应填写的目标地址。客户端应使用`127.0.0.1`、服务器网卡IP或主机名。

外部主机能否访问，还取决于：

1. 服务进程是否运行。
2. 是否监听正确协议、地址和端口。
3. 客户端到服务器的路由是否正常。
4. 主机防火墙是否允许。
5. SELinux或应用自身是否限制访问。

交互观察：[Socket、TCP、HTTP与TLS端到端访问动画](../../../animations/06-socket-tcp-http-tls/index.html)。先完成“Socket与监听”和“TCP连接”，再进行下面的双终端练习。

## 2.2.5 双终端观察监听地址

本练习在`rocky-server`上完成。打开终端A和终端B。

### 第一步：准备页面

在终端A创建目录：

```bash
mkdir -p ~/course-practice/m2/ch22
```

打开文件：

```bash
vim ~/course-practice/m2/ch22/index.html
```

写入：

```html
<h1>Socket practice</h1>
```

保存并退出。

### 第二步：只监听回环地址

在终端A启动服务：

```bash
python3 -m http.server 18080 --bind 127.0.0.1 --directory ~/course-practice/m2/ch22
```

这条命令会占用终端A，属于正常现象。保持它运行，不要继续在终端A输入命令。

在终端B查看监听：

```bash
ss -lnt
```

在结果中找到`127.0.0.1:18080`。

在终端B通过回环地址访问：

```bash
curl http://127.0.0.1:18080/
```

预期能够看到`Socket practice`。

在终端B通过本机主机名访问：

```bash
curl --connect-timeout 3 http://rocky-server:18080/
```

如果`rocky-server`解析为网卡地址，本次访问应失败，因为服务只监听`127.0.0.1`。

### 第三步：结束服务

回到终端A按`Ctrl+C`。然后在终端B确认监听消失：

```bash
ss -lnt
```

### 第四步：监听所有IPv4接口

在终端A重新启动：

```bash
python3 -m http.server 18080 --bind 0.0.0.0 --directory ~/course-practice/m2/ch22
```

在终端B查看监听：

```bash
ss -lnt
```

此时应看到`0.0.0.0:18080`。

通过回环地址访问：

```bash
curl http://127.0.0.1:18080/
```

通过主机名访问：

```bash
curl http://rocky-server:18080/
```

两次请求都应进入该监听。完成观察后，回到终端A按`Ctrl+C`。

## 2.2.6 使用nc测试TCP端口

Rocky Linux 9安装`nc`：

```bash
sudo dnf install -y nmap-ncat
```

Ubuntu 22.04安装`nc`前先刷新索引：

```bash
sudo apt update
```

安装软件包：

```bash
sudo apt install -y netcat-openbsd
```

在`ubuntu-client`测试`rocky-server`的SSH端口：

```bash
nc -vz -w 3 rocky-server 22
```

测试一个通常没有服务监听的端口：

```bash
nc -vz -w 3 rocky-server 9999
```

常见结果：

| 现象 | 可以直接说明什么 | 仍需检查什么 |
|---|---|---|
| `succeeded` | TCP握手成功 | 应用协议和认证是否正常 |
| `Connection refused` | 目标返回拒绝 | 服务是否监听、监听地址是否正确、防火墙是否主动拒绝 |
| `timed out` | 限定时间内没有完成握手 | 路由、丢弃型防火墙、目标状态 |
| `No route to host` | 当前网络路径或拒绝信息异常 | `ip route get`、网关和防火墙 |

这些现象都不是唯一根因。服务端`ss`、服务状态和日志，必须与客户端`nc`结果一起判断。

## 本章练习：建立端口证据链

在`rocky-server`完成：

1. 启动`127.0.0.1:18080`，记录`ss`结果。

3. 改为`0.0.0.0:18080`，再次记录`ss`结果。
4. 在`ubuntu-client`使用`nc`测试22、18080和9999。

6. 回到服务所在终端按`Ctrl+C`，确认18080监听消失。
