## 学习目标

完成本章后，应能够：

1. 说明“进程监听”和“防火墙放行”是两个不同条件。
2. 说明firewalld、nftables和iptables的关系。
3. 找出网卡当前进入的活动zone。
4. 区分firewalld的service与port规则。
5. 区分运行时配置与永久配置。
6. 按最小开放原则设计基础规则。

## 2.9.1 防火墙位于访问链的哪一层

外部请求到达服务前，需要同时满足：

```text
客户端路由正确
→ 数据包到达服务器网卡
→ firewalld规则允许
→ 目标地址和端口存在监听
→ 应用处理请求
```

因此：

- `firewall-cmd --add-port`成功，不代表端口上一定有服务。
- `ss`看到监听，不代表外部客户端一定能够访问。
- 客户端访问失败，应同时检查监听和防火墙。

## 2.9.2 firewalld、nftables与iptables

Rocky Linux 9通常使用：

```text
管理员使用firewall-cmd
→ firewalld管理规则
→ nftables在内核数据路径中执行规则
```

`iptables`命令可能作为兼容工具存在，但本课程统一使用firewalld管理主机防火墙，避免多套工具产生不一致状态。

安装：

```bash
sudo dnf install -y firewalld
```

启动并设置开机启动：

```bash
sudo systemctl enable --now firewalld
```

检查状态：

```bash
firewall-cmd --state
```

预期输出`running`。

## 2.9.3 zone表示信任边界

zone是一组规则的集合。网卡或来源地址进入某个zone后，由该zone决定允许哪些服务和端口。

查看默认zone：

```bash
firewall-cmd --get-default-zone
```

查看活动zone及其网卡：

```bash
firewall-cmd --get-active-zones
```

查看全部zone名称：

```bash
firewall-cmd --get-zones
```

默认zone不一定等于当前网卡实际所在zone。修改规则前，必须以`--get-active-zones`的结果为准。

假设实际活动区域为`public`，查看规则：

```text
firewall-cmd --zone=public --list-all
```

实际不是`public`时，必须替换成真实区域。

交互观察：[firewalld区域、规则与安全变更动画](../../../animations/09-firewalld-zones-rules/index.html)。先完成“流量与Zone”。

## 2.9.4 service与port

查看预定义服务：

```bash
firewall-cmd --get-services
```

查看SSH服务定义：

```bash
firewall-cmd --info-service=ssh
```

查看HTTP服务定义：

```bash
firewall-cmd --info-service=http
```

两种规则：

| 方式 | 示例 | 适合场景 |
|---|---|---|
| service | `--add-service=http` | 使用标准服务定义 |
| port | `--add-port=8080/tcp` | 应用使用自定义端口 |

service不仅是一个显示名称，它可能包含多个端口、协议或辅助信息。标准服务优先使用service，自定义实验端口使用port。

## 2.9.5 运行时与永久配置

firewalld保存两套状态：

| 状态 | 修改方式 | 重启或reload后 |
|---|---|---|
| 运行时 | 默认`firewall-cmd` | 丢失，或被永久配置重建 |
| 永久 | 添加`--permanent` | 不会立即进入当前运行时 |

查看活动区域的运行时配置：

```text
firewall-cmd --zone=<实际活动区域> --list-all
```

查看永久配置：

```text
firewall-cmd --permanent --zone=<实际活动区域> --list-all
```

`reload`会使用永久配置重建运行时状态：

```bash
sudo firewall-cmd --reload
```

如果只添加了运行时规则，reload后该规则会消失。如果只添加永久规则但没有reload，当前访问不会立即改变。

## 2.9.6 安全的规则变更顺序

推荐顺序：

```text
确认服务监听
→ 找到实际活动zone
→ 保存变更前规则
→ 添加运行时规则
→ 从真实客户端验证
→ 写入永久配置
→ reload
→ 再次验证运行时和永久状态
```

这样可以先验证功能，再决定是否持久保存。

添加8080运行时规则的格式：

```text
sudo firewall-cmd --zone=<实际活动区域> --add-port=8080/tcp
```

查询：

```text
firewall-cmd --zone=<实际活动区域> --query-port=8080/tcp
```

移除：

```text
sudo firewall-cmd --zone=<实际活动区域> --remove-port=8080/tcp
```

本章只理解流程，实际变更安排在实验12，避免与实验9的临时规则混淆。

## 2.9.7 最小开放原则

每条允许规则都应回答：

1. 哪个服务确实需要对外提供？
2. 使用什么协议和端口？
3. 哪些来源需要访问？
4. 规则需要临时还是永久？
5. 如何验证？
6. 如何回滚？

不应：

- 为排障直接停止firewalld。
- 一次开放大范围端口。
- 把数据库端口暴露给所有来源。
- 只看到`success`就认为业务访问成功。

检查firewalld配置语法：

```bash
sudo firewall-cmd --check-config
```

## 2.9.8 Ubuntu UFW对照

Ubuntu常使用UFW作为防火墙前端。

查看状态：

```bash
sudo ufw status verbose
```

本课程`ubuntu-client`不对外提供业务服务，因此不要求为了练习而开放8080。需要理解的是：不同发行版前端命令不同，但都在管理主机网络访问策略。

## 本章练习：只读安全基线

在`rocky-server`逐条执行并填写：

| 项目 | 命令 | 实际结果 |
|---|---|---|

| 默认zone | `firewall-cmd --get-default-zone` | |

4. reload对只存在于运行时的规则有什么影响？

本章练习不修改规则。实验12会使用8080完成运行时、永久和回滚闭环。
