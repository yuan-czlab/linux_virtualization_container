# 2.7 SSH客户端配置与文件传输

> 所属课程：《Linux操作系统》
> 所属模块：模块二 网络远程管理与基础防护
> 学习前置：2.5 SSH远程管理、2.6 SSH密钥认证
> 对应实验：实验10“SSH远程管理与密钥认证”
> 学习方式：编辑客户端配置 → 检查最终参数 → 远程执行 → 传输并校验

## 学习目标

完成本章后，应能够：

1. 使用`~/.ssh/config`为两台Rocky配置易记别名。
2. 使用`ssh -G`检查客户端最终采用的参数。
3. 判断远程命令中的内容由本地Shell还是远端Shell展开。
4. 使用`scp`完成上传、下载和目录传输。
5. 使用`sftp`区分本地目录与远程目录。
6. 使用SHA256验证传输前后内容是否一致。

## 2.7.1 为什么需要SSH客户端配置

没有配置文件时，每次都要重复输入：

```text
ssh -i ~/.ssh/linux-course-ed25519 rocky-server@rocky-server
```

`~/.ssh/config`可以把目标地址、用户名、端口和密钥组合成一个别名：

```text
ssh rs
```

配置文件只影响当前客户端用户，不会修改服务端`sshd`。

继续使用[SSH信任、认证与文件传输动画](../../../animations/07-ssh-trust-auth-transfer/index.html)的“配置与命令”和“文件传输”。

## 2.7.2 安全编辑~/.ssh/config

本节在`ubuntu-client`完成。

确认SSH目录：

```bash
mkdir -p ~/.ssh
```

设置目录权限：

```bash
chmod 700 ~/.ssh
```

检查是否已有配置：

```bash
ls -l ~/.ssh/config
```

如果文件已经存在并且还没有本章备份，先保存：

```bash
cp -a ~/.ssh/config ~/.ssh/config.before-m2
```

已经存在`config.before-m2`时不要覆盖，先查看两个文件。

打开配置：

```bash
vim ~/.ssh/config
```

加入：

```sshconfig
Host rs rocky-server
    HostName rocky-server
    User rocky-server
    Port 22
    IdentityFile ~/.ssh/linux-course-ed25519
    IdentitiesOnly yes

Host rw rocky-web
    HostName rocky-web
    User rocky-web
    Port 22
    IdentityFile ~/.ssh/linux-course-ed25519
    IdentitiesOnly yes

Host *
    ServerAliveInterval 60
    ServerAliveCountMax 3
```

字段含义：

| 字段 | 作用 |
|---|---|
| `Host` | 客户端使用的别名或匹配模式 |
| `HostName` | 实际解析的服务器名称或地址 |
| `User` | 远端登录用户名 |
| `Port` | 服务端端口 |
| `IdentityFile` | 客户端私钥路径 |
| `IdentitiesOnly` | 只使用明确配置的身份 |
| `ServerAliveInterval` | 空闲时发送保活请求的间隔 |
| `ServerAliveCountMax` | 连续无响应多少次后断开 |

设置文件权限：

```bash
chmod 600 ~/.ssh/config
```

## 2.7.3 使用ssh -G验证最终参数

检查`rs`：

```bash
ssh -G rs | grep -E '^(hostname|user|port|identityfile|identitiesonly) '
```

检查`rw`：

```bash
ssh -G rw | grep -E '^(hostname|user|port|identityfile|identitiesonly) '
```

`ssh -G`不会登录服务器，只显示客户端解析配置后的最终参数。

同一行的两个名称指向同一组参数，所以`ssh rs`和`ssh rocky-server`都能使用课程密钥。OpenSSH很多客户端选项采用“先取得的值生效”，因此专用Host应放在通用`Host *`之前。

测试别名登录：

```bash
ssh rs
```

登录后确认主机名：

```bash
hostnamectl --static
```

退出：

```bash
exit
```

测试第二台服务器：

```bash
ssh rw
```

## 2.7.4 远程执行单条命令

不进入交互终端，直接查询远端主机名：

```bash
ssh rs 'hostnamectl --static'
```

查询远端运行时间：

```bash
ssh rs 'uptime'
```

查询远端根文件系统：

```bash
ssh rw 'df -h /'
```

查看远端SSH服务：

```bash
ssh rw 'systemctl is-active sshd'
```

命令的退出状态会通过SSH返回到本地，自动化工具会据此判断任务是否成功。

## 2.7.5 本地展开与远端展开

推荐把远程命令放在单引号中：

```bash
ssh rs 'echo "remote_host=$(hostname) remote_time=$(date -Iseconds)"'
```

外层单引号阻止本地Shell提前展开`$(hostname)`和`$(date ...)`，它们会被发送到远端后再执行。

如果使用双引号：

```text
ssh rs "echo local_host=$(hostname)"
```

`$(hostname)`会先在`ubuntu-client`展开，远端只收到展开后的普通文字。

远程命令越复杂，引号和退出状态越容易出错。复杂任务应先拆成多条可验证命令，后续再交给Ansible、Paramiko或Fabric。

## 2.7.6 使用scp上传文件

在Ubuntu创建练习目录：

```bash
mkdir -p ~/course-practice/m2/ch27
```

打开本地文件：

```bash
vim ~/course-practice/m2/ch27/transfer.txt
```

写入：

```text
SSH file transfer practice
```

计算本地哈希：

```bash
sha256sum ~/course-practice/m2/ch27/transfer.txt
```

上传到`rocky-server`：

```bash
scp ~/course-practice/m2/ch27/transfer.txt rs:/tmp/
```

`scp`基本格式：

```text
scp <源> <目标>
```

带有`主机:路径`的一侧是远端。不带主机前缀的一侧是本地。

## 2.7.7 下载文件

从`rocky-server`下载主机名文件：

```bash
scp rs:/etc/hostname ~/course-practice/m2/ch27/rocky-server-hostname.txt
```

查看下载结果：

```bash
cat ~/course-practice/m2/ch27/rocky-server-hostname.txt
```

下载到目录时，应先确保本地目录存在，避免误解目标位置。

## 2.7.8 传输目录

创建本地目录：

```bash
mkdir -p ~/course-practice/m2/ch27/upload-dir
```

创建第一个文件：

```bash
touch ~/course-practice/m2/ch27/upload-dir/a.txt
```

创建第二个文件：

```bash
touch ~/course-practice/m2/ch27/upload-dir/b.txt
```

递归上传：

```bash
scp -r ~/course-practice/m2/ch27/upload-dir rw:/tmp/
```

在远端检查：

```bash
ssh rw 'find /tmp/upload-dir -maxdepth 1 -type f -printf "%f\n"'
```

使用`-r`前必须确认源目录和目标目录，避免把不需要的大目录传到服务器。

## 2.7.9 使用哈希验证完整性

查看本地哈希：

```bash
sha256sum ~/course-practice/m2/ch27/transfer.txt
```

查看远端哈希：

```bash
ssh rs 'sha256sum /tmp/transfer.txt'
```

两个SHA256值相同，说明传输前后文件内容一致。

哈希相同不能证明：

- 文件传到了正确的业务目录。
- 远端所有者和权限正确。
- 文件内容安全可信。

因此还要检查位置、所有者和权限：

```bash
ssh rs 'ls -l /tmp/transfer.txt'
```

## 2.7.10 使用sftp交互传输

连接：

```bash
sftp rs
```

进入`sftp>`提示符后，可逐条输入：

```text
pwd
lpwd
ls
lls
cd /tmp
lcd ~/course-practice/m2/ch27
put transfer.txt
get transfer.txt sftp-download.txt
exit
```

命令含义：

| 命令 | 作用 |
|---|---|
| `pwd` | 查看远端当前目录 |
| `lpwd` | 查看本地当前目录 |
| `ls` | 列出远端文件 |
| `lls` | 列出本地文件 |
| `cd` | 切换远端目录 |
| `lcd` | 切换本地目录 |
| `put` | 本地上传到远端 |
| `get` | 从远端下载到本地 |

传输方向不明确时，先执行`pwd`和`lpwd`，再执行`put`或`get`。

## 本章练习：可验证文件交付

在`ubuntu-client`完成：

1. 使用`ssh -G`证明`rs`和`rw`分别指向正确主机、用户和密钥。
2. 创建`delivery.txt`，写入自己的姓名、日期和课程名称。
3. 计算本地SHA256。
4. 使用`scp`上传到`rs:/tmp/`。
5. 使用`ssh`计算远端SHA256并检查所有者。
6. 从远端下载为`delivery-return.txt`。
7. 使用`diff`比较原文件和下载文件。

比较：

```bash
diff ~/course-practice/m2/ch27/delivery.txt ~/course-practice/m2/ch27/delivery-return.txt
```

`diff`没有输出且退出状态为0，表示两个文件内容一致。
