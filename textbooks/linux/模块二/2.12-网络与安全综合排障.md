# 2.12 网络与安全综合排障

> 所属课程：《Linux操作系统》
> 所属模块：模块二 网络远程管理与基础防护
> 学习前置：2.1～2.11及实验8～12
> 对应实验：实验13“Linux网络与访问故障综合排查”
> 学习方式：明确故障 → 建立基线 → 分层取证 → 单点修复 → 原路径复测

## 学习目标

完成本章后，应能够：

1. 把“访问不了”转换成可复现的故障描述。
2. 按名称、网络、端口、服务、防火墙、权限和日志分层取证。
3. 根据错误类型选择下一条最小只读检查命令。
4. 区分直接现象、推测和已经证实的根因。
5. 一次只修改一个原因，并使用原客户端路径复测。
6. 编写包含回退与预防措施的故障报告。

## 2.12.1 排障不是随机执行命令

不合格做法：

- 同时重启网络、服务和防火墙。
- 删除配置后重新安装软件。
- 看到超时就判断是防火墙。
- 使用`chmod 777`或关闭SELinux“试一下”。
- 只在服务器本机验证，不返回原客户端。

正确流程：

```text
描述故障
→ 确认正常基线和最近变更
→ 从客户端复现
→ 按层收集证据
→ 提出一个可验证假设
→ 只修改一个因素
→ 从原客户端复测
→ 检查相关功能没有回归
→ 记录回退和预防措施
```

交互观察：[Linux网络与访问分层故障推理动画](../../../animations/11-layered-troubleshooting/index.html)。

## 2.12.2 把模糊描述变成测试条件

“服务器访问不了”缺少关键信息。故障受理至少填写：

| 项目 | 示例 |
|---|---|
| 客户端 | ubuntu-client |
| 目标 | rocky-server |
| 使用名称或IP | rocky-server |
| 协议 | HTTP |
| 端口 | 8080 |
| 操作 | `curl http://rocky-server:8080/` |
| 原始错误 | Connection timed out |
| 首次发生时间 | 具体时间 |
| 影响范围 | 一台客户端还是全部客户端 |
| 最近变更 | 防火墙、服务、网络或配置 |

必须保留原始错误，不能只写“失败”。

## 2.12.3 正常基线

故障实验必须先证明无故障状态。

客户端基线：

```bash
getent hosts rocky-server
```

```bash
ip route get "$(getent ahostsv4 rocky-server | awk 'NR==1 {print $1}')"
```

```bash
nc -vz -w 3 rocky-server 22
```

```bash
ssh rocky-server 'hostnamectl --static'
```

服务端基线：

```bash
systemctl is-active sshd
```

```bash
sudo ss -lntp
```

```bash
firewall-cmd --get-active-zones
```

```bash
getenforce
```

只有目标业务在客户端正常成功后，才能开始注入故障。

## 2.12.4 分层证据链

### 第一层：名称解析

```bash
getent hosts rocky-server
```

```bash
dig +short rocky-server
```

`getent`成功而`dig`失败，可能是名称来自`/etc/hosts`，不代表系统应用无法解析。

### 第二层：地址和路由

```bash
ip -brief address
```

```bash
ip route
```

```text
ip route get <目标实际IPv4>
```

### 第三层：TCP端口

```bash
nc -vz -w 3 rocky-server 8080
```

`refused`、`timed out`和`No route to host`只是方向性证据，不能单独确定根因。

### 第四层：服务与监听

```text
systemctl status <实际服务名> --no-pager
```

```bash
sudo ss -lntp
```

服务active但只监听`127.0.0.1`时，外部客户端仍无法访问。

### 第五层：防火墙

```bash
firewall-cmd --get-active-zones
```

```text
firewall-cmd --zone=<实际活动区域> --list-all
```

规则必须检查实际活动zone，同时比较service、port和rich rule。

### 第六层：DAC与SELinux

```text
namei -l <服务需要访问的文件>
```

```text
ls -lZ <服务需要访问的文件>
```

```bash
getenforce
```

```bash
sudo ausearch -m AVC,USER_AVC -ts recent
```

只有存在与故障时间和对象相符的证据，才能判断SELinux参与拒绝。

### 第七层：应用协议与日志

```text
curl -v --connect-timeout 3 http://<目标>:<端口>/
```

```text
journalctl -u <实际服务名> --since '10 minutes ago' --no-pager
```

HTTP 404说明连接和HTTP响应已经发生，问题与TCP超时不同。

## 2.12.5 用现象缩小范围

| 已知现象 | 优先检查 | 暂时不能得出的结论 |
|---|---|---|
| 名称失败，IP成功 | hosts、NSS、DNS | 服务器宕机 |
| 本机成功，外部超时 | 监听地址、防火墙、路由 | 应用文件损坏 |
| 外部立即refused | 服务和监听 | 一定是防火墙丢弃 |
| TCP成功，HTTP 404 | URL和站点内容 | 网络不通 |
| SSH端口成功，认证失败 | 用户、密钥、权限、日志 | 22端口被阻断 |
| 服务日志出现AVC | 标签、布尔值、策略需求 | 应关闭SELinux |

## 2.12.6 一次只改一个因素

如果同时执行：

```text
重启服务 + 开放防火墙 + 修改hosts + setenforce 0
```

即使恢复，也无法证明根因。

合格修复应包含：

1. 证据支持的单一判断。
2. 修改前原值。
3. 一条明确修复操作。
4. 同一测试重新执行。
5. 相关服务、SSH和安全状态回归检查。

## 2.12.7 修复后必须回到原路径

原始故障如果发生在Ubuntu访问Rocky：

- 只在Rocky运行`curl 127.0.0.1`不算恢复。
- 必须回到Ubuntu，使用原名称、原协议、原端口和原操作复测。
- 还要确认SSH、firewalld和SELinux没有被破坏。

推荐回归矩阵：

| 检查 | 预期 |
|---|---|
| `getent hosts rocky-server` | 地址正确 |
| `ssh rocky-server hostname` | 身份正确 |
| 目标HTTP请求 | 状态和内容正确 |
| `systemctl is-active firewalld` | active |
| `getenforce` | Enforcing |
| 临时规则和进程 | 已按要求清理 |

## 2.12.8 故障报告模板

```markdown
# 故障编号与标题

## 1. 故障现象与影响范围

## 2. 正常基线与最近变更

## 3. 检查过程与关键证据

## 4. 判断与根因

## 5. 修复操作

## 6. 原客户端复测与回归检查

## 7. 回退方法

## 8. 预防措施
```

报告中应区分：

- 事实：命令实际输出。
- 判断：由事实得到的结论。
- 操作：实际修改。
- 结果：修复后复测。

## 本章练习：选择下一条证据

为以下现象各写一条最优先的只读命令，并说明原因：

1. `getent hosts rocky-server`返回错误地址。
2. Rocky本机8080成功，Ubuntu访问超时。
3. `nc`连接22成功，但SSH提示Permission denied。
4. 服务active，但`ss`没有目标监听。
5. 文件权限看似正确，服务日志出现AVC。

不要给出一串命令，也不要直接写修复命令。练习目标是根据当前证据选择下一步。

## 模块二验收清单

- 三机静态地址和hosts正确。
- SSH主机指纹和用户密钥正确。
- `rocky-server`与`rocky-web`可通过课程SSH配置登录。
- firewalld保持active，只有必要规则。
- SELinux保持Enforcing。
- rsync备份可以恢复。
- 每个故障都有“现象—证据—根因—修复—复测”。
