# 3.6 Shell服务器巡检

> 所属课程：《Linux操作系统》
> 所属模块：模块三 企业服务器部署与综合运维
> 对应整册教材：第30章
> 对应实验：实验19 Shell服务器巡检脚本
> 学习路径：先验证单条命令 → 理解Shell结构 → 编写最小脚本 → 分段增加检查 → 验证异常与退出码

本章把前面已经掌握的`df`、`systemctl`、`ss`、`curl`等命令组织成一个可重复执行的巡检脚本。脚本运行在`rocky-server`，检查本机资源、MySQL、MongoDB、Redis和SSH，并通过HTTP访问`rocky-web`的健康页。

Shell脚本是本章的学习对象，因此最终会形成完整脚本。但学习顺序不是直接复制大段代码，而是先逐条理解和验证命令，再一次增加一个结构，每次修改后立即检查。

## 3.6.1 项目情境与学习目标

TechCorp管理员每天需要检查：

- 当前检查的是不是`rocky-server`；
- 根分区容量是否接近上限；
- 可用内存是否过低；
- MySQL、MongoDB、Redis和SSH是否运行；
- 22、3306、27017和6379端口是否监听；
- `rocky-web`健康页是否可以访问。

如果完全依赖人工输入，可能漏项，也难以让其他程序判断结果。因此需要把已经验证过的只读命令固化为脚本，并约定：

- 退出码0：全部检查正常；
- 退出码1：存在资源警告；
- 退出码2：存在服务、端口或访问故障。

完成本章后，应能够：

1. 区分Shell、Bash、终端和脚本文件；
2. 使用变量、引用、命令替换和参数；
3. 使用`if`、`[[ ]]`、函数、数组和循环组织检查；
4. 区分标准输出、标准错误和退出码；
5. 通过逐段验证形成只读巡检脚本；
6. 主动制造受控故障并证明脚本能够识别和恢复。

## 3.6.2 Shell、Bash与脚本

Shell是用户与操作系统交互的一类命令解释器，Bash是常见Shell实现。终端中输入命令属于交互使用；把命令和控制结构写入文件，就形成脚本。

查看当前登录Shell：

```bash
printf '%s\n' "$SHELL"
```

查看Bash版本：

```bash
bash --version
```

查看命令实际来自哪里：

```bash
type -a bash
```

Shell脚本适合自动执行顺序明确、输入边界清楚的重复任务。它不意味着可以跳过对每一条底层命令的理解。

## 3.6.3 先验证单条巡检命令

在写脚本之前，先证明每一项检查在当前主机上能独立工作。

查看主机名：

```bash
hostnamectl --static
```

查看根分区容量：

```bash
df -h /
```

使用适合脚本解析的POSIX格式：

```bash
df -P /
```

查看内存：

```bash
free -h
```

读取内核提供的内存数据：

```bash
grep -E '^(MemTotal|MemAvailable):' /proc/meminfo
```

查看1、5、15分钟平均负载：

```bash
cat /proc/loadavg
```

查看服务状态：

```bash
systemctl is-active redis
```

查看监听端口：

```bash
ss -lntH
```

访问Web健康页：

```bash
curl --fail --max-time 3 -H 'Host: techcorp.test' http://rocky-web/health
```

只有这些命令单独执行时符合预期，才适合加入脚本。脚本不能把错误的手工命令自动变正确。

## 3.6.4 最小脚本与Shebang

一个最小Bash脚本可以只有三部分：

```bash-script
#!/usr/bin/env bash
set -u
printf 'host=%s\n' "$(hostnamectl --static)"
```

第一行称为Shebang：

```text
#!/usr/bin/env bash
```

直接执行文件时，系统根据它选择解释器。`/usr/bin/env bash`会从当前命令搜索路径中找到Bash，具有较好的可移植性。

`set -u`使脚本引用未定义变量时报告错误，可帮助发现拼写问题。但对于可选变量，需要显式提供默认值。

只检查语法，不运行脚本：

```bash
bash -n server-health.sh
```

赋予所有者和同组用户执行权限：

```bash
chmod 750 server-health.sh
```

直接执行：

```bash
./server-health.sh
```

也可以显式交给Bash执行：

```bash
bash server-health.sh
```

两者的区别是：`./server-health.sh`需要执行权限并使用Shebang；`bash server-health.sh`由当前命令明确选择Bash。

## 3.6.5 变量、赋值与引用

变量赋值的等号两侧不能有空格：

在同一个终端中依次输入赋值和读取命令：

```console
$ DISK_WARN=90
$ printf 'disk_warn=%s\n' "$DISK_WARN"
disk_warn=90
```

双引号允许变量展开，并把展开结果作为一个整体：

```console
$ message='Redis service is active'
$ printf '%s\n' "$message"
Redis service is active
```

单引号中的`$`不会展开：

```console
$ printf '%s\n' '$message'
$message
```

编写脚本时，变量引用默认使用`"$变量"`，除非明确需要Shell进行字段拆分或通配符展开。

环境变量会传递给子进程，普通Shell变量默认不会。查看环境变量：

```bash
printenv HOME
```

巡检阈值、服务数组和最终状态是脚本自身变量，不需要全部导出为环境变量。

## 3.6.6 命令替换与数据采集

命令替换`$(命令)`把命令输出保存到变量中：

```console
$ host_name=$(hostnamectl --static)
$ printf 'host=%s\n' "$host_name"
host=rocky-server
```

采集根分区使用率数字：

```console
$ disk_used=$(df -P / | awk 'NR==2 {gsub(/%/, "", $5); print $5}')
$ printf 'disk_used=%s%%\n' "$disk_used"
disk_used=以当前系统实际结果为准
```

这条管道执行了以下处理：

1. `df -P /`输出根分区稳定格式；
2. `awk`只处理第2行；
3. `gsub`删除第5列中的百分号；
4. `print`输出纯数字，便于整数比较。

不要直接假设采集结果一定是数字。设备、命令或输出格式发生变化时，空字符串也可能进入变量。

## 3.6.7 位置参数与默认值

脚本可以从命令行接收参数：

| 写法 | 含义 |
|---|---|
| `$0` | 脚本名称 |
| `$1` | 第一个参数 |
| `$2` | 第二个参数 |
| `$#` | 参数个数 |
| `"$@"` | 保持边界的全部参数 |

在启用`set -u`后，如果没有传入第一个参数，直接读取`$1`会报错。可以提供默认值：

```bash
target=${1:-/}
```

`${1:-/}`表示第一个参数不存在或为空时使用`/`。本章最终巡检脚本将检查对象写入集中配置，不要求从命令行传入密码或秘密。

## 3.6.8 条件测试与if

判断文件是否存在：

```bash
[[ -f /etc/os-release ]]
```

立即查看上一条命令的退出码：

```bash
printf 'exit=%s\n' "$?"
```

常见测试：

| 写法 | 含义 |
|---|---|
| `[[ -f "$path" ]]` | 是普通文件 |
| `[[ -d "$path" ]]` | 是目录 |
| `[[ -n "$value" ]]` | 字符串非空 |
| `[[ "$state" == active ]]` | 字符串相等 |
| `[[ "$value" =~ ^[0-9]+$ ]]` | 字符串由一位或多位数字组成 |
| `(( used >= limit ))` | 整数算术比较 |

基本条件结构：

```bash-script
if systemctl is-active --quiet redis; then
    printf '[OK] Redis is active\n'
else
    printf '[CRIT] Redis is not active\n' >&2
fi
```

`if`判断的是命令退出码：0进入`then`，非0进入`else`。它不是只判断屏幕上是否有文字。

## 3.6.9 标准输入、标准输出与标准错误

Linux进程默认具有三个标准数据流：

| 编号 | 名称 | 常见用途 |
|---:|---|---|
| 0 | stdin | 输入 |
| 1 | stdout | 普通结果 |
| 2 | stderr | 错误和严重异常 |

普通结果写到标准输出：

```bash
printf '[OK] service active\n'
```

严重异常写到标准错误：

```bash
printf '[CRIT] service failed\n' >&2
```

只保存标准输出：

```bash
./server-health.sh > health.stdout.log
```

只保存标准错误：

```bash
./server-health.sh 2> health.stderr.log
```

把标准输出和标准错误保存到同一文件：

```bash
./server-health.sh > health-all.log 2>&1
```

重定向顺序会影响结果。`2>&1`表示让标准错误指向“此时标准输出所在的位置”。

## 3.6.10 退出码与严重程度

Shell用0表示成功，非0表示不同类型的失败。查看刚刚执行命令的退出码：

```bash
printf '%s\n' "$?"
```

`$?`只保存最近一条命令的状态。执行任何新命令后，它就会被覆盖，因此必须立即记录。

本课程巡检脚本约定：

| 退出码 | 级别 | 含义 |
|---:|---|---|
| 0 | OK | 全部检查通过 |
| 1 | WARN | 资源达到预警阈值，但核心服务仍可用 |
| 2 | CRITICAL | 服务、端口或跨机健康检查失败 |

多项检查同时发生时，应保留最高严重程度。例如磁盘达到警告阈值后又发现Redis停止，最终状态必须从1升级为2，不能被后面的正常检查改回0。

## 3.6.11 函数与局部变量

函数把重复逻辑集中起来：

```bash-script
ok() {
    printf '[OK] %s\n' "$1"
}
```

调用函数：

```bash
ok 'Redis is active'
```

函数内部变量可使用`local`限制作用范围：

```bash-script
check_service() {
    local service=$1
    systemctl is-active --quiet "$service"
}
```

`local service=$1`把传入的第一个参数保存为函数局部变量，避免意外覆盖脚本中的同名全局变量。

巡检脚本中的函数应尽量承担单一职责，例如分别检查磁盘、内存、服务、端口和Web健康页。

## 3.6.12 数组与循环

数组适合保存同类检查对象：

```bash
SERVICES=(mysqld mongod redis sshd)
```

查看全部元素：

```bash
printf '%s\n' "${SERVICES[@]}"
```

循环逐个处理：

```bash-script
for service in "${SERVICES[@]}"; do
    printf 'checking=%s\n' "$service"
done
```

`"${SERVICES[@]}"`能够保持每个数组元素的边界。本项目不把`nginx`加入`rocky-server`的本机服务数组，因为Nginx运行在`rocky-web`。跨主机Web服务应由`curl`检查其功能入口。

## 3.6.13 资源阈值不是普遍真理

磁盘使用率判断示例：

```bash-script
if (( disk_used >= DISK_WARN )); then
    printf '[WARN] disk=%s%%\n' "$disk_used"
fi
```

可用内存百分比可以根据`/proc/meminfo`计算：

```text
可用内存百分比 = MemAvailable × 100 ÷ MemTotal
```

阈值需要结合实际环境：

- 磁盘增长速度和扩容需要多久；
- 服务器是否存在短时缓存；
- 内存不足是否已经导致交换或进程被终止；
- 负载平均值与CPU逻辑核数的关系；
- 告警出现后是否有人能够处理。

课程使用固定阈值练习条件判断，不代表所有生产服务器都应使用相同数字。

## 3.6.14 服务、端口与业务检查不能互相替代

```text
systemctl active
      │ 只能证明服务管理器认为进程在运行
      ▼
端口正在监听
      │ 只能证明进程接受该地址和端口的连接
      ▼
客户端请求成功
      │ 证明协议和应用功能进一步通过
      ▼
业务数据正确
      └ 还需要认证、查询或读写验证
```

例如Redis服务可能为`active`，6379也在监听，但客户端仍可能因为认证失败而无法读取业务键。因此综合验收不能只选其中一层。

本章脚本不保存数据库密码，只检查本机服务和端口；数据库认证与数据正确性继续由实验15—17中的专用客户端验证。

## 3.6.15 为什么巡检脚本不盲目使用set -e

`set -e`会在某些非0命令出现时使Shell退出，但其行为会受到条件语句、管道、函数和子Shell上下文影响。

巡检脚本的目标恰恰是发现失败后继续检查其他项目。如果第一个异常就退出，管理员可能看不到后续故障。因此本课程脚本：

- 使用`set -u`发现未定义变量；
- 在`if`中显式判断可能失败的命令；
- 用`STATUS`累计最高严重程度；
- 不依赖`set -e`代替错误处理。

这并不表示`set -e`永远不能使用，而是使用前必须理解目标和上下文。

## 3.6.16 只读巡检、监控与自动修复

| 类型 | 主要作用 | 是否持续运行 | 是否主动修改系统 |
|---|---|---|---|
| 巡检 | 某一时刻收集并判断状态 | 通常否 | 默认否 |
| 监控 | 持续采集、保存趋势并告警 | 是 | 通常不直接修复 |
| 自动修复 | 满足条件时执行恢复动作 | 可能持续 | 是 |

入门巡检脚本默认只读，不自动重启服务、不开放防火墙、不删除日志。错误判断如果与自动修复绑定，可能形成反复重启、掩盖根因或扩大故障。

## 3.6.17 脚本质量验证

脚本至少要经历以下检查：

1. `bash -n`检查语法；
2. `shellcheck`静态分析（环境可用时）；
3. 正常环境执行；
4. 保存并立即读取退出码；
5. 主动制造一个可恢复故障；
6. 确认异常输出和非0退出码；
7. 恢复服务后再次执行；
8. 检查日志中是否泄露密码；
9. 审查Git差异后再提交。

语法通过不代表逻辑正确。只有正常、异常和恢复三种路径都经过验证，才能说明脚本具备基本可用性。

## 3.6.18 常见错误

| 错误 | 可能后果 | 改进方式 |
|---|---|---|
| 一开始复制完整脚本 | 不理解变量来源和检查逻辑 | 分段编写，每段立即验证 |
| 变量不加引号 | 空格和通配符导致参数拆分 | 默认使用`"$var"` |
| 未验证采集结果就算术比较 | 空值或文本导致表达式错误 | 先用正则检查数字 |
| 只检查systemd状态 | 端口或业务仍可能失败 | 增加端口和HTTP检查 |
| 把`nginx`加入错误主机 | 正常环境也始终报告失败 | 按主机角色设计检查对象 |
| 输出密码供脚本测试 | 密码进入日志和Git | 认证测试使用专用安全流程 |
| 得到异常就自动重启 | 掩盖根因或形成重启循环 | 默认只报告，由人员判断 |
| 查看退出码前先执行其他命令 | `$?`已被覆盖 | 紧跟脚本执行记录退出码 |

## 3.6.19 本章练习：逐步编写文件检查器

本练习用一个很短的脚本理解参数、条件、标准错误和退出码，不一次粘贴完整脚本。

### 步骤一：准备目录和测试文件

```bash
mkdir -p ~/course-practice/m3/ch30
```

```bash
printf 'ready\n' > ~/course-practice/m3/ch30/ready.txt
```

### 步骤二：创建最小脚本

```bash
vim ~/course-practice/m3/ch30/check-file.sh
```

先输入：

```bash-script
#!/usr/bin/env bash
set -u
target=${1:-}
printf 'target=%s\n' "$target"
```

保存后检查语法：

```bash
bash -n ~/course-practice/m3/ch30/check-file.sh
```

传入存在的测试文件：

```bash
bash ~/course-practice/m3/ch30/check-file.sh ~/course-practice/m3/ch30/ready.txt
```

### 步骤三：增加条件和退出码

重新编辑脚本：

```bash
vim ~/course-practice/m3/ch30/check-file.sh
```

把最后一行替换为：

```bash-script
if [[ -f "$target" ]]; then
    printf '[OK] file=%s\n' "$target"
    exit 0
fi

printf '[CRIT] missing=%s\n' "$target" >&2
exit 2
```

保存后再次检查语法：

```bash
bash -n ~/course-practice/m3/ch30/check-file.sh
```

执行成功路径：

```bash
bash ~/course-practice/m3/ch30/check-file.sh ~/course-practice/m3/ch30/ready.txt
```

立即查看退出码：

```bash
printf 'exit=%s\n' "$?"
```

执行失败路径：

```bash
bash ~/course-practice/m3/ch30/check-file.sh ~/course-practice/m3/ch30/missing.txt
```

立即查看退出码：

```bash
printf 'exit=%s\n' "$?"
```

### 练习验收

- `ready.txt`由前序步骤真实创建；
- 每增加一段脚本都重新执行`bash -n`；
- 文件存在时输出到stdout并返回0；
- 文件不存在时输出到stderr并返回2；
- 能说明为什么`$?`必须立即读取。

## 3.6.20 本章小结

1. 自动化之前必须先证明单条命令正确。
2. 变量和命令替换负责保存配置与采集结果，变量引用默认应加双引号。
3. `if`根据命令退出码选择分支，函数和数组帮助减少重复。
4. stdout面向普通结果，stderr面向异常，退出码面向调用脚本的程序。
5. 巡检脚本应累计最高严重程度，不应在第一个失败处停止全部检查。
6. 语法检查不能代替正常、异常和恢复测试。
7. 本课程脚本默认只读，不把巡检直接变成自动修复。
