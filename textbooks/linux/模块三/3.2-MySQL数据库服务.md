# 3.2 MySQL数据库服务

> 所属课程：《Linux操作系统》
> 所属模块：模块三 企业服务器部署与综合运维
> 学习前置：MySQL数据库原理、systemd、端口、firewalld和备份恢复
> 对应实验：实验15“MySQL数据库服务部署与备份恢复”
> 主要主机：`rocky-server`

## 学习目标

完成本章后，应能够：

1. 说明`mysqld`、客户端、Socket、TCP端口和数据目录的关系。
2. 完成MySQL首次启动、临时密码处理和状态检查。
3. 根据`'用户'@'来源'`理解账号匹配和最小权限。
4. 区分本地Socket、本机TCP和远程TCP连接。
5. 使用监听、账号来源和firewalld建立三道远程访问边界。
6. 完成逻辑备份、文件检查、隔离恢复和正式恢复。

## 3.2.1 本章定位

数据库原理及SQL已经在前置课程学习。本章重点不是重复全部SQL语法，而是把MySQL作为Linux企业服务进行运维：

```text
软件仓库
→ 软件包
→ systemd服务
→ Socket和TCP监听
→ 用户与来源
→ 防火墙
→ 日志
→ 备份与恢复
```

## 3.2.2 主要组件

| 对象 | 常见名称或路径 | 作用 |
|---|---|---|
| 服务进程 | `mysqld` | 接收连接、执行SQL、管理数据 |
| 命令行客户端 | `mysql` | 连接服务器并执行SQL |
| 逻辑备份工具 | `mysqldump` | 导出建表语句和数据 |
| systemd Unit | `mysqld.service` | 管理服务 |
| 数据目录 | `/var/lib/mysql` | 保存数据文件 |
| 主配置 | `/etc/my.cnf` | 配置入口 |
| 配置片段 | `/etc/my.cnf.d/*.cnf` | 独立功能配置 |
| 错误日志 | 常见为`/var/log/mysqld.log` | 初始化和运行错误 |
| TCP端口 | 3306 | 网络连接入口 |

## 3.2.3 安装来源

Rocky系统自带仓库可能提供MariaDB。课程使用MySQL Community时，应在安装前检查冲突：

```bash
rpm -qa | grep -Ei '^(mysql|mariadb)'
```

MySQL Yum仓库配置RPM的文件名会更新，因此教材不固定小版本下载链接。每学期使用已经验证的EL9仓库RPM或离线包。

安装仓库RPM的格式：

```text
sudo dnf install -y ~/course-packages/<本学期验证的MySQL仓库RPM>
```

安装服务端：

```bash
sudo dnf install -y mysql-community-server
```

检查：

```bash
rpm -q mysql-community-server mysql-community-client
```

## 3.2.4 首次启动

启动：

```bash
sudo systemctl enable --now mysqld
```

检查：

```bash
systemctl is-active mysqld
```

```bash
systemctl is-enabled mysqld
```

查看日志：

```bash
sudo journalctl -u mysqld -n 50 --no-pager
```

通过RPM首次初始化时，随机临时root密码通常记录在错误日志。只在本人屏幕查看：

```bash
sudo grep 'temporary password' /var/log/mysqld.log
```

使用临时密码登录：

```bash
mysql -u root -p
```

在MySQL提示符修改为符合策略的强实验密码：

```sql
ALTER USER 'root'@'localhost' IDENTIFIED BY '<教师指定的强实验密码>';
```

尖括号内容必须替换，密码不写入作业和Git。

## 3.2.5 MySQL账号包含来源

以下是不同账号：

```text
'app_user'@'localhost'
'app_user'@'127.0.0.1'
'app_user'@'192.168.200.30'
'app_user'@'%'
```

MySQL会根据客户端来源选择匹配账号。`'user'@'%'`允许广泛来源，不适合作为课程远程访问默认做法。

查看当前连接：

```sql
SELECT USER(), CURRENT_USER();
```

- `USER()`显示客户端提交的用户和连接来源。
- `CURRENT_USER()`显示服务器实际匹配并用于授权的账号。

## 3.2.6 最小权限

创建业务库：

```sql
CREATE DATABASE company_db CHARACTER SET utf8mb4;
```

创建本地业务账号：

```sql
CREATE USER 'app_user'@'localhost' IDENTIFIED BY '<业务实验密码>';
```

只授予业务库常用数据权限：

```sql
GRANT SELECT, INSERT, UPDATE, DELETE ON company_db.* TO 'app_user'@'localhost';
```

查看：

```sql
SHOW GRANTS FOR 'app_user'@'localhost';
```

业务账号不授予全局`ALL PRIVILEGES`，也不授予用户管理权限。

## 3.2.7 Socket、本机TCP与远程TCP

不指定`-h`时通常使用Unix Socket：

```bash
mysql -u root -p
```

强制本机TCP：

```bash
mysql --protocol=TCP -h 127.0.0.1 -P 3306 -u app_user -p
```

远程TCP：

```text
mysql -h <rocky-server实际IPv4> -P 3306 -u remote_app -p
```

三种入口可能匹配不同`'user'@'host'`账号，不能把所有Access denied都简单判断为密码错误。

## 3.2.8 远程访问的三道边界

```text
第一道：mysqld是否监听服务器网卡地址
第二道：MySQL是否存在匹配客户端来源的账号和权限
第三道：firewalld是否只允许该来源访问3306
```

查看监听：

```bash
sudo ss -lntp | grep ':3306 '
```

查看有效变量：

```bash
mysql -u root -p -e "SHOW VARIABLES WHERE Variable_name IN ('port','bind_address','datadir','log_error');"
```

配置片段示例：

```ini
[mysqld]
bind-address=0.0.0.0
```

扩大监听后必须同时收紧账号来源和firewalld。验证完成后，本课程会恢复为`127.0.0.1`，数据库不长期对外开放。

## 3.2.9 配置变更流程

```text
备份配置
→ 新建独立cnf片段
→ 检查内容
→ restart
→ systemctl检查
→ ss检查监听
→ 本机连接
→ 远程连接
→ 日志检查
```

MySQL没有与`nginx -t`完全相同的通用简单检查流程，因此更要使用独立配置片段、控制台和明确回退文件。

## 3.2.10 逻辑备份

创建逻辑备份：

```bash
mysqldump -u root -p --single-transaction --routines --events --triggers --no-tablespaces company_db > ~/backup-lab/mysql/company_db.sql
```

重要选项：

| 选项 | 作用 |
|---|---|
| `--single-transaction` | 对InnoDB进行一致性事务快照，避免长时间锁表 |
| `--routines` | 包含存储过程和函数 |
| `--events` | 包含事件 |
| `--triggers` | 包含触发器；默认通常已启用 |
| `--no-tablespaces` | 避免导出表空间语句及相关额外权限需求 |

`--single-transaction`不能保证对非事务表获得同样一致性，备份期间也应避免改变表结构。

## 3.2.11 备份文件必须检查

退出状态：

```bash
echo $?
```

文件非空：

```bash
test -s ~/backup-lab/mysql/company_db.sql
```

查看开头：

```bash
sed -n '1,30p' ~/backup-lab/mysql/company_db.sql
```

查找目标表：

```bash
grep -n 'CREATE TABLE.*employees' ~/backup-lab/mysql/company_db.sql
```

重定向会在mysqldump失败时仍创建空文件，所以“文件存在”不等于备份成功。

## 3.2.12 隔离恢复

先创建独立数据库：

```sql
CREATE DATABASE company_restore CHARACTER SET utf8mb4;
```

恢复：

```bash
mysql -u root -p company_restore < ~/backup-lab/mysql/company_db.sql
```

验证：

```bash
mysql -u root -p company_restore -e 'SELECT COUNT(*) FROM employees;'
```

恢复测试必须检查表结构、行数和关键数据，不能只看命令没有报错。

## 3.2.13 常见故障

| 现象 | 优先检查 |
|---|---|
| Socket连接失败 | mysqld状态、Socket路径、错误日志 |
| TCP refused | 监听地址、端口、服务状态 |
| TCP timeout | 路由和firewalld |
| Access denied | `USER()`、`CURRENT_USER()`、账号host、密码和授权 |
| 服务启动失败 | 新配置片段、journal、错误日志、数据目录权限 |
| 备份为0字节 | mysqldump错误和退出状态 |
| 恢复提示表已存在 | 是否误恢复到非空数据库 |
