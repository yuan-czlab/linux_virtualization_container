## 3.1.1 Nginx的角色

Nginx常用于：

- 提供静态文件。
- 作为反向代理转发请求。
- 终止HTTPS连接。
- 按主机名和URI路由请求。
- 进行基础负载分配和访问控制。

```text
ubuntu-client
→ rocky-web:80
→ Nginx选择server
→ Nginx选择location
→ 读取静态文件或转发上游
→ 返回HTTP响应
```

本实验先在`rocky-web`本机运行上游；实验20再迁移为`rocky-web→rocky-server`跨主机代理。

## 3.1.2 master与worker

Nginx通常包含：

| 进程 | 主要职责 |
|---|---|
| master | 读取配置、管理worker、处理重载 |
| worker | 接受连接并处理请求 |

查看进程：

```bash
ps -ef | grep '[n]ginx'
```

`systemctl reload nginx`让master重新读取配置并平滑替换worker，通常不会像完整重启那样直接中断已有连接。

## 3.1.3 安装与服务管理

在Rocky安装：

```bash
sudo dnf install -y nginx
```

查看版本：

```bash
nginx -v
```

启动并设置开机启动：

```bash
sudo systemctl enable --now nginx
```

检查状态：

```bash
systemctl status nginx --no-pager
```

检查监听：

```bash
sudo ss -lntp | grep ':80 '
```

## 3.1.4 重要路径

| 路径 | 作用 |
|---|---|
| `/etc/nginx/nginx.conf` | 主配置 |
| `/etc/nginx/conf.d/*.conf` | 独立站点或功能配置 |
| `/usr/share/nginx/html/` | 默认站点目录 |
| `/var/log/nginx/access.log` | 默认访问日志 |
| `/var/log/nginx/error.log` | 默认错误日志 |

查看主配置是否包含`conf.d`：

```bash
grep -n 'include.*conf.d' /etc/nginx/nginx.conf
```

## 3.1.5 配置层次

简化结构：

```nginx
http {
    server {
        listen 80;
        server_name techcorp.test;

        location / {
            root /srv/techcorp/www;
            index index.html;
        }
    }
}
```

- `http`定义HTTP层公共配置。
- `server`表示一个虚拟主机。
- `location`按URI选择处理规则。
- 指令能否写在某个位置取决于它允许的上下文。

## 3.1.6 server选择

客户端请求包含Host：

```http
GET / HTTP/1.1
Host: techcorp.test
```

Nginx通常根据监听地址、端口和`server_name`选择server。若没有匹配名称，会进入该监听上的默认server。

因此“直接访问IP看到默认页面”不代表自定义站点没有加载。应使用正确名称或临时Host请求头验证：

```bash
curl -H 'Host: techcorp.test' http://rocky-web/
```

## 3.1.7 location与root

配置：

```nginx
location /docs/ {
    root /srv/techcorp/www;
}
```

请求`/docs/guide.html`时，典型文件路径为：

```text
/srv/techcorp/www + /docs/guide.html
= /srv/techcorp/www/docs/guide.html
```

`root`通常会把完整URI追加到目录后。路径判断错误是404的重要来源。

精确匹配：

```nginx
location = /health {
    return 200 "ok\n";
}
```

只匹配`/health`，不会匹配`/health/other`。

交互观察：[Nginx请求路由、静态资源与反向代理动画](../../../animations/12-nginx-request-routing-proxy/index.html)。

## 3.1.8 反向代理

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:5000/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

访问`/api/health.json`时，结尾斜杠会使上游收到`/health.json`。

反向代理故障需要分别检查：

1. Nginx入口是否可达。
2. 上游进程是否运行。
3. 上游地址和端口是否监听。
4. `proxy_pass`路径是否正确。
5. SELinux是否允许httpd域建立网络连接。
6. error log记录的具体原因。

## 3.1.9 安全变更流程

```text
保存当前配置
→ 小范围编辑
→ nginx -t
→ reload
→ systemctl确认状态
→ 本机curl
→ 外部客户端curl
→ 检查日志
```

语法检查：

```bash
sudo nginx -t
```

查看合并后的完整配置：

```bash
sudo nginx -T
```

配置错误时不能执行reload。根据错误中的文件和行号修复。

## 3.1.10 日志

访问日志通常记录客户端、请求、状态码、响应大小和时间。

查看：

```bash
sudo tail -n 20 /var/log/nginx/access.log
```

错误日志记录文件不存在、权限拒绝、上游连接失败等：

```bash
sudo tail -n 20 /var/log/nginx/error.log
```

常见状态：

| 状态 | 本章常见方向 |
|---|---|
| 200 | 请求成功 |
| 403 | 目录无索引、DAC或SELinux拒绝 |
| 404 | URI映射后文件不存在 |
| 502 | 上游地址错误、进程停止或被策略阻止 |

状态码只是入口，根因应由配置和日志支持。

## 3.1.11 firewalld与SELinux

标准HTTP服务规则：

```text
sudo firewall-cmd --permanent --zone=<实际活动区域> --add-service=http
```

自定义站点目录需要正确DAC权限和SELinux标签：

```text
sudo semanage fcontext -a -t httpd_sys_content_t '/srv/techcorp/www(/.*)?'
```

应用：

```bash
sudo restorecon -RFv /srv/techcorp/www
```

反向代理连接上游通常需要：

```bash
sudo setsebool -P httpd_can_network_connect on
```

只有确实使用反向代理时才开启，不通过关闭SELinux解决502。
