## 学习目标

完成本章后，应能够：

1. 区分数据库、集合、文档、字段、嵌套对象和数组。
2. 说明`mongod`、`mongosh`、配置文件、数据目录和27017端口。
3. 按安全顺序创建首个管理员并启用认证。
4. 区分用户、认证数据库和角色授权。
5. 使用`bindIp`和认证建立本地访问边界。
6. 使用`mongodump`和`mongorestore`完成隔离恢复验证。

## 3.3.1 文档模型

关系数据库主要以表、行和列组织数据；MongoDB以BSON文档组织数据。

```javascript
{
  host: "rocky-server",
  service: {
    name: "mongod",
    port: 27017
  },
  status: "ok",
  tags: ["database", "course"]
}
```

| 对象 | 示例 |
|---|---|
| 数据库 | `company_db` |
| 集合 | `inspections` |
| 文档 | 上面的完整对象 |
| 字段 | `host`、`status` |
| 嵌套对象 | `service` |
| 数组 | `tags` |

同一集合中的文档可以有不同字段，但这不意味着不需要数据约束。生产系统通常仍需应用验证或Schema Validation。

交互观察：[MongoDB文档模型、认证、RBAC与备份动画](../../../animations/14-mongodb-document-auth-rbac/index.html)。

## 3.3.2 服务组件

| 对象 | 名称或路径 |
|---|---|
| 数据库服务 | `mongod` |
| Shell客户端 | `mongosh` |
| 配置文件 | `/etc/mongod.conf` |
| 数据目录 | `/var/lib/mongo` |
| 日志目录 | `/var/log/mongodb` |
| 默认端口 | 27017 |
| 备份工具 | `mongodump`、`mongorestore` |

`mongosh`只是客户端，安装客户端不等于数据库服务已经运行。

## 3.3.3 平台与安装来源

MongoDB 8.0官方文档列出Rocky Linux 9的64位支持。安装前检查：

```bash
uname -m
```

```bash
lscpu
```

```bash
lscpu | grep -i avx
```

老旧CPU或虚拟机没有暴露所需指令集时，可能出现`Illegal instruction`。这不是通过重装软件就能解决的问题。

仓库地址和签名密钥可能随版本变化，每学期应按官方安装页核对，不从未知镜像混装服务端、Shell和Database Tools。

## 3.3.4 服务管理

启动：

```bash
sudo systemctl enable --now mongod
```

检查状态：

```bash
systemctl is-active mongod
```

检查监听：

```bash
sudo ss -lntp | grep ':27017 '
```

查看systemd日志：

```bash
sudo journalctl -u mongod -n 50 --no-pager
```

查看MongoDB日志：

```bash
sudo tail -n 50 /var/log/mongodb/mongod.log
```

## 3.3.5 基础文档操作

连接本机：

```bash
mongosh --host 127.0.0.1 --port 27017
```

选择数据库：

```javascript
use company_db
```

插入：

```javascript
db.inspections.insertOne({host:"rocky-server", service:"mongod", status:"ok"})
```

查询：

```javascript
db.inspections.find()
```

统计：

```javascript
db.inspections.countDocuments({})
```

更新：

```javascript
db.inspections.updateOne({service:"mongod"}, {$set:{status:"checked"}})
```

## 3.3.6 认证数据库

MongoDB用户属于创建它的数据库。连接时应明确`authenticationDatabase`。

```text
courseAdmin创建在admin
→ 使用--authenticationDatabase admin

inspectionApp创建在company_db
→ 使用--authenticationDatabase company_db
```

“业务数据库”和“认证数据库”可能相同，也可能不同。

## 3.3.7 安全启用认证顺序

课程采用：

```text
保持bindIp为127.0.0.1
→ 创建首个课程管理员
→ 启用security.authorization
→ 重启并验证未认证访问受限
→ 使用管理员认证
→ 创建业务用户和最小角色
```

首个管理员必须具有管理其他用户的能力。MongoDB还提供localhost exception，但它只在实例没有任何用户或角色时生效，不能当作长期后门。

创建管理员时使用交互密码：

```javascript
use admin
```

```javascript
db.createUser({user:"courseAdmin", pwd:passwordPrompt(), roles:[{role:"userAdminAnyDatabase",db:"admin"},{role:"readWriteAnyDatabase",db:"admin"},{role:"dbAdminAnyDatabase",db:"admin"}]})
```

启用配置：

```yaml
security:
  authorization: enabled
```

## 3.3.8 业务用户与RBAC

管理员认证：

```bash
mongosh --host 127.0.0.1 --authenticationDatabase admin -u courseAdmin -p
```

创建业务用户：

```javascript
use company_db
```

```javascript
db.createUser({user:"inspectionApp", pwd:passwordPrompt(), roles:[{role:"readWrite",db:"company_db"}]})
```

业务用户不应具有用户管理和其他数据库写权限。

## 3.3.9 bindIp与网络边界

配置：

```yaml
net:
  port: 27017
  bindIp: 127.0.0.1
```

YAML使用空格缩进，Tab可能导致解析失败。

本课程最终只监听回环地址，不开放27017。需要远程访问时必须同时规划：

- `bindIp`。
- 身份认证和角色。
- firewalld来源。
- TLS加密。
- 日志审计。

只把`bindIp`改成`0.0.0.0`并开放端口是不安全的。

## 3.3.10 逻辑备份

本节属于必须理解的运维知识，但不占用实验16的2学时操作时间。实验16保留已经创建的文档和账号，实验20再执行正式备份和隔离恢复，避免在同一短实验中同时堆叠安装、认证和恢复任务。

为业务库创建BSON逻辑备份：

```bash
mongodump --host 127.0.0.1 --port 27017 --authenticationDatabase company_db -u inspectionApp -p --db company_db --out ~/backup-lab/mongodb/company-dump
```

不在命令行直接写密码，`-p`会交互询问。

检查文件：

```bash
find ~/backup-lab/mongodb/company-dump -type f -ls
```

## 3.3.11 隔离恢复

使用管理员恢复并把命名空间映射到独立数据库：

```bash
mongorestore --host 127.0.0.1 --port 27017 --authenticationDatabase admin -u courseAdmin -p --nsFrom='company_db.*' --nsTo='company_restore.*' ~/backup-lab/mongodb/company-dump
```

检查恢复数据：

```bash
mongosh --host 127.0.0.1 --authenticationDatabase admin -u courseAdmin -p company_restore
```

```javascript
db.inspections.countDocuments({})
```

备份存在不等于可恢复。必须核对文档数量和关键字段。

## 3.3.12 常见故障

| 现象 | 优先检查 |
|---|---|
| mongod启动失败 | YAML缩进、键名、日志、目录权限、CPU支持 |
| 27017 refused | 服务状态和监听 |
| Authentication failed | 用户、密码、认证数据库 |
| Unauthorized | 已认证，但角色不允许当前操作 |
| 本机成功远程失败 | bindIp、防火墙、路由 |
| 恢复数量不一致 | 备份目录、命名空间映射和目标库 |
