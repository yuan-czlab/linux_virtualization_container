## 1.3.1 虚拟磁盘格式

KVM常见磁盘格式包括raw与qcow2：

| 对比项 | raw | qcow2 |
|---|---|---|
| 结构 | 接近原始块设备 | 带元数据的QEMU写时复制格式 |
| 空间 | 可预分配，也可稀疏 | 支持按需增长 |
| 快照 | 依赖外部方案 | 支持内部或外部快照能力 |
| 功能 | 简单、开销较低 | 后备文件、压缩等功能更丰富 |

查看镜像信息：

```bash
qemu-img info /var/lib/libvirt/images/course-vm01.qcow2
```

“虚拟大小”是客户机看到的容量，“磁盘实际占用”是当前在宿主机使用的空间，两者可能不同。

## 1.3.2 写时复制与后备链

qcow2可以让新镜像引用只读基础镜像，新增写入保存到覆盖层：

```text
course-base.qcow2（基础镜像，不修改）
├── vm01-overlay.qcow2（保存vm01差异）
└── vm02-overlay.qcow2（保存vm02差异）
```

优点是创建快、节省空间；风险是覆盖层依赖后备文件。移动、改名或损坏基础镜像会使多个客户机同时失效。因此必须记录后备链并保护基础镜像。

## 1.3.3 镜像复制与校验

教师下发的基础镜像应带固定文件名、版本和SHA-256校验值。学生先验证再复制：

```bash
sha256sum course-base.qcow2
```

```bash
qemu-img info course-base.qcow2
```

校验和用于发现传输损坏或文件版本不一致，不等同于恶意代码安全审计。不要直接让多台虚拟机以可写方式共用同一个基础磁盘。

## 1.3.4 快照的用途和边界

快照记录某一时刻的磁盘状态，适合教学实验前创建回退点。按实现可分为内部快照和外部快照；按一致性可讨论崩溃一致与应用一致。

- 崩溃一致快照类似突然断电后的磁盘状态，文件系统通常能恢复，但应用缓存中的数据可能丢失。
- 应用一致快照会协调数据库或应用完成刷盘、冻结或备份，恢复质量更高。

常用查看操作：

```bash
sudo virsh snapshot-list course-vm01
```

```bash
sudo virsh snapshot-info course-vm01 --snapshotname before-change
```

快照与原虚拟机通常位于同一宿主机或同一存储故障域。源磁盘损坏时，快照也可能不可用，因此快照不是备份。

## 1.3.5 克隆后的唯一性

克隆不仅是复制磁盘。新虚拟机至少需要检查：

- libvirt虚拟机名称和UUID；
- 虚拟网卡MAC地址；
- 客户机主机名；
- DHCP租约或静态IP；
- `/etc/machine-id`；
- SSH主机密钥；
- 应用实例标识与日志归属。

如果两个克隆拥有相同网络身份或系统标识，会造成地址冲突、安全告警和自动化系统误判。模板制作应清理或在首次启动时重新生成唯一信息。

## 1.3.6 备份与恢复闭环

可靠的镜像备份至少包含：

```text
虚拟机配置XML
+ 虚拟磁盘或可重建的镜像链
+ 文件校验值
+ 版本与时间记录
+ 恢复步骤
+ 恢复验证结果
```

只复制正在高速写入的虚拟磁盘，可能得到不一致副本。课堂中应在关机或明确协调后备份；生产环境则需选择存储快照、客户机代理或应用备份方案。

## 1.3.7 容量与链路排查

```bash
df -hT
```

```bash
du -sh /var/lib/libvirt/images/*
```

```bash
qemu-img info --backing-chain vm01-overlay.qcow2
```

```bash
sudo virsh domblklist course-vm01
```

排查顺序是：确认虚拟机实际引用哪个磁盘，再确认磁盘格式与后备链，最后检查宿主机空间和权限。不要仅凭文件名推断关系。

## 1.3.8 qcow2按需分配的含义

qcow2把虚拟磁盘划分为可管理的数据区域，并维护从客户机逻辑块到宿主文件位置的映射。新建一个20GB qcow2文件时，宿主机可能只占很小空间；客户机不断写入后，实际占用才增加。

删除客户机文件不一定立即缩小宿主qcow2文件，因为客户机文件系统释放空间与镜像回收空间是两个层次。判断容量时要同时看：

```text
宿主文件系统剩余空间
→ qcow2文件实际占用
→ qcow2虚拟容量
→ 客户机文件系统使用量
```

基础教学阶段不要在唯一镜像上尝试不熟悉的压缩、缩减或修复操作。先复制镜像，在副本上验证。

## 1.3.9 快照、克隆与备份决策

| 需求 | 更合适的手段 | 原因 |
|---|---|---|
| 配置实验前快速回退 | 快照 | 创建和回退快，但仍依赖原存储 |
| 从统一模板创建多台虚拟机 | 克隆或覆盖层 | 快速生成独立实例 |
| 宿主机损坏后恢复 | 独立备份 | 副本位于不同故障域 |
| 跨平台长期归档 | 磁盘、XML、校验和与恢复文档 | 同时保存数据和重建信息 |
| 数据库一致性恢复 | 应用级备份配合镜像备份 | 仅磁盘状态不能保证业务一致 |

同一个动作可能组合使用。例如在关机状态下导出XML、复制磁盘并计算校验和，这是面向恢复的归档；在改配置前创建内部快照，则是短期回退点。

## 1.3.10 镜像链的安全变更原则

1. 先用`domblklist`确认虚拟机实际磁盘。
2. 再用`qemu-img info --backing-chain`确认依赖。
3. 记录虚拟机是否运行以及数据一致性要求。
4. 对基础镜像和关键覆盖层建立独立副本。
5. 只对明确副本执行转换、合并或修复实验。
6. 完成后不仅检查镜像结构，还要启动客户机并验证网络、文件和服务。

`qemu-img check`等工具可以检查镜像结构，但修复参数可能改变数据。发现损坏时先保留原文件，不在唯一副本上直接尝试修复。

### 本章小结

qcow2为教学环境提供按需增长、快照和后备文件等能力，但同时引入镜像链依赖。模板、快照、克隆和备份是四个不同概念，交付时必须同时管理唯一性、完整性和可恢复性。

### 本章短练习：观察qcow2稀疏空间

本章位于实验2之后，`qemu-img`应已可用：

先创建本章独立练习目录：

```bash
mkdir -p ~/course-practice/vc-m1/ch03
```

确认练习镜像名称尚未被占用：

```bash
test ! -e ~/course-practice/vc-m1/ch03/practice.qcow2
```

创建1GB空qcow2镜像：

```bash
qemu-img create -f qcow2 ~/course-practice/vc-m1/ch03/practice.qcow2 1G
```

逐项观察镜像信息、表面大小和实际占用：

```bash
qemu-img info ~/course-practice/vc-m1/ch03/practice.qcow2
```

```bash
ls -lh ~/course-practice/vc-m1/ch03/practice.qcow2
```

```bash
du -h ~/course-practice/vc-m1/ch03/practice.qcow2
```

最后执行只读结构检查：

```bash
qemu-img check ~/course-practice/vc-m1/ch03/practice.qcow2
```

比较虚拟容量、文件表面大小和实际占用；该空镜像不定义为虚拟机，也不作为后续基础镜像。正式镜像链、克隆、快照和恢复在实验3完成。
