## 1.5.1 从KVM到OpenStack

在单台KVM主机上，管理员直接操作虚拟机、镜像和网络。当规模扩大后，还需要解决多宿主机调度、租户隔离、配额、身份、网络服务、自助申请和统一接口。OpenStack把计算、网络、镜像、身份等能力组织为云平台服务。

本课程只要求使用教师预建平台完成用户侧资源操作，不部署OpenStack。部署与集群管理会在后续《云计算应用》课程继续学习。

## 1.5.2 用户视角的核心对象

| OpenStack对象 | 作用 | 与KVM实验的联系 |
|---|---|---|
| Project | 隔离用户资源和配额 | 一组课程实验资源 |
| Image | 创建实例的系统模板 | qcow2基础镜像 |
| Flavor | 规定vCPU、内存和磁盘规格 | 虚拟机资源参数 |
| Network/Subnet | 提供实例网络 | libvirt虚拟网络 |
| Security Group | 控制进入或离开实例的流量 | 分布式虚拟防火墙规则 |
| Key Pair | 注入登录公钥 | SSH密钥认证 |
| Instance | 用户获得的云主机 | KVM虚拟机实例 |

## 1.5.3 创建云主机的依赖关系

```text
身份与项目权限
├── 配额
├── 镜像
├── 规格
├── 网络/子网
├── 安全组规则
└── 密钥对
        ↓
      实例
        ↓
 地址 + SSH + 服务验证
```

实例创建失败时，应先看平台事件和状态，再检查配额、镜像、网络和调度条件。实例显示`ACTIVE`只代表云平台认为计算实例已运行，仍需验证地址、端口、登录和客户机内部服务。

## 1.5.4 安全组与最小开放

安全组规则应围绕业务需求配置。SSH实验只开放TCP 22，并优先限制来源地址；不应为了省事开放全部协议和全部来源。安全组、客户机防火墙和应用监听共同决定访问结果：

```text
客户端
→ 平台网络路径
→ 安全组
→ 客户机防火墙
→ 应用监听地址与端口
```

任意一层不满足条件都会导致访问失败。

## 1.5.5 密钥对与登录

平台保存公钥，用户妥善保管私钥。私钥文件应限制权限，不放入公开仓库，不在报告中粘贴完整内容。以下是登录语法模板，三个中文词都必须替换为平台实际信息：

```text
chmod 600 私钥文件
ssh -i 私钥文件 镜像默认用户@实例地址
```

不同镜像的默认用户可能不同，应以教师发布的镜像清单为准。

## 1.5.6 资源配额与回收

云资源是有限、可计量的。实验结束后按依赖关系回收临时实例、安全组和密钥记录，但应先保存报告证据。删除云主机通常不可恢复，必须确认名称、项目和提交要求。

## 1.5.7 模块交付文档

模块一最终文档至少包括：

- 嵌套虚拟化环境检查结果；
- KVM软件栈和虚拟机清单；
- 镜像来源、版本、校验和与后备链；
- 两台虚拟机的地址、网络和服务验证；
- 一次故障注入、定位和恢复记录；
- OpenStack实例的镜像、规格、网络、安全组和登录证据；
- 已回收与保留资源清单；
- 风险、限制和后续建议。

## 1.5.9 OpenStack主要服务关系

OpenStack由可组合服务构成，不是单一进程。用户体验实验涉及的主要服务包括：

| 服务 | 常见项目名 | 核心职责 |
|---|---|---|
| 身份服务 | Keystone | 用户、项目、角色、令牌和服务目录 |
| 镜像服务 | Glance | 保存和提供云主机镜像 |
| 计算服务 | Nova | 实例生命周期、调度和计算节点协作 |
| 网络服务 | Neutron | 网络、子网、端口、地址与安全组 |
| 块存储 | Cinder | 向实例提供可挂载卷 |
| Web界面 | Horizon | 调用各服务API提供用户界面 |

底层计算节点可使用KVM运行实例，但用户通常不直接登录计算节点执行`virsh`。云平台通过服务API、数据库、消息和代理协作完成调度与配置。

## 1.5.10 创建实例背后的流程

从用户点击“创建实例”到能够SSH，大致经历：

```text
Keystone验证身份和项目权限
→ Nova检查请求与配额
→ 调度器选择满足资源条件的计算节点
→ Glance提供镜像
→ Neutron创建端口并配置网络与安全组
→ 计算节点通过Hypervisor创建实例
→ 注入元数据或SSH公钥
→ 实例启动并获得地址
→ 用户从允许的网络路径连接
```

不同部署会增加卷、浮动IP和高可用组件。这个流程帮助判断错误来源：配额不足、镜像不可用、无可用主机、网络端口异常和客户机启动失败不是同一类问题。

## 1.5.11 镜像、临时磁盘与云硬盘

镜像是创建实例的模板，实例系统盘可能是计算节点上的临时磁盘，也可能由块存储卷提供。删除实例时，临时系统盘通常随实例删除；独立云硬盘是否保留由创建方式和删除选项决定。

因此创建和删除前要回答：

- 数据写在实例临时磁盘还是独立卷？
- 删除实例是否同时删除启动卷？
- 备份是镜像快照、卷快照还是应用备份？
- 重新创建实例后如何恢复身份、网络和业务数据？

## 1.5.12 配额与调度不是同一个概念

配额规定项目最多能够申请多少资源；调度判断当前是否存在满足条件的实际位置。项目仍有vCPU配额，不代表某个计算节点一定有足够连续内存；规格合法，也不代表镜像、网络和可用域组合一定可调度。

用户侧排障应记录实例状态、Fault信息、操作事件和所选对象，再向平台管理员提供可复现请求。不要连续创建多个同名实例加剧资源占用。

## 1.5.13 云平台使用者的交付责任

平台负责提供资源能力，但使用者仍负责客户机内部操作系统、账号、公钥、服务配置、数据和补丁。安全组开放22端口后，SSH服务仍可能未启动；平台实例状态正常后，应用仍可能故障。这种责任边界是后续云计算和企业运维课程的重要基础。

### 本章小结

OpenStack不是“另一种虚拟机软件”，而是把计算、镜像、网络、身份和配额组织成云服务。学生通过预建平台完成一次真实云主机生命周期，重点理解对象依赖、自助交付、安全开放和资源回收。
