## 1.1.1 为什么需要虚拟化

传统方式下，一项业务独占一台物理服务器。业务负载较低时，大量CPU和内存闲置；更换硬件时还需要重新安装系统和迁移应用。虚拟化在物理资源与操作系统之间增加抽象层，使一台物理机能够运行多台相互隔离的虚拟机。

虚拟化常见价值包括：

- 提高物理资源利用率；
- 缩短新服务器交付时间；
- 通过模板、快照和克隆提高环境一致性；
- 隔离不同业务或实验环境；
- 为资源池化、自动调度和云计算奠定基础。

虚拟化并不自动等于高可用或安全。单台物理宿主机故障仍可能影响其上的全部虚拟机；快照也不能替代独立备份。

## 1.1.2 虚拟化的基本对象

| 对象 | 含义 | 本课程实例 |
|---|---|---|
| 宿主机 | 提供CPU、内存、磁盘和网络的系统 | Windows物理机或Rocky KVM主机 |
| 虚拟机 | 获得虚拟硬件并运行完整操作系统的实例 | course-vm01 |
| Hypervisor | 创建和调度虚拟机的虚拟化层 | VMware、KVM |
| 虚拟磁盘 | 以文件或逻辑卷表示的虚拟块设备 | qcow2文件 |
| 虚拟网卡 | 提供给虚拟机的网络接口 | virtio网卡 |
| 虚拟网络 | 连接虚拟机和外部网络的逻辑网络 | libvirt default网络 |

## 1.1.3 Type 1与Type 2虚拟化

教材常按Hypervisor与硬件的关系进行分类：

```text
Type 1（裸机型）                 Type 2（宿主型）
应用/虚拟机                     应用/虚拟机
Hypervisor                     虚拟化软件
物理硬件                        宿主操作系统
                                物理硬件
```

生产环境中的边界可能比这张图复杂。KVM把Linux内核转变为能够运行虚拟机的Hypervisor，管理工具仍运行在Linux用户空间；VMware Workstation则安装在Windows宿主操作系统上。本课程重点是理解职责，而不是只记分类答案。

## 1.1.4 全虚拟化、半虚拟化与硬件辅助

- 全虚拟化让客户机看到一套完整虚拟硬件，客户机通常不需要知道自己运行在虚拟机中。
- 半虚拟化通过客户机与Hypervisor协作降低某些模拟开销。
- Intel VT-x、AMD-V等CPU扩展帮助Hypervisor高效执行客户机的特权指令。
- virtio是一组面向虚拟化环境的高性能设备接口，常用于虚拟磁盘、网卡和内存设备。

实际KVM虚拟机通常同时使用硬件辅助虚拟化与virtio设备，因此这些概念不是互相排斥的产品选项。

## 1.1.5 虚拟化、模拟、容器与云计算

| 技术 | 主要抽象对象 | 是否运行独立内核 | 典型用途 |
|---|---|---:|---|
| 模拟 | 指令集或完整硬件 | 是 | 跨架构运行、硬件研究 |
| 虚拟机 | 一套虚拟硬件 | 是 | 多操作系统、强隔离、传统业务 |
| 容器 | 操作系统进程与资源视图 | 否，共享宿主机内核 | 应用快速交付、微服务 |
| 云计算 | 可服务化交付的资源池 | 取决于服务 | 按需、自助、计量、弹性管理 |

云计算会使用虚拟化，但虚拟化资源池只有配合身份、网络、配额、自动化和服务接口，才具备更完整的云平台特征。

## 1.1.6 嵌套虚拟化

本课程环境存在两层虚拟化：

```text
Windows物理机
└── VMware中的rocky-server（第一层客户机）
    └── KVM创建的Linux虚拟机（第二层客户机）
```

要让Rocky中的KVM使用硬件虚拟化，物理CPU、主板固件、Windows虚拟化占用情况和VMware设置都必须满足条件。常见检查包括：

```bash
lscpu | grep -E 'Virtualization|Hypervisor'
```

```bash
grep -Eoc '(vmx|svm)' /proc/cpuinfo
```

```bash
lsmod | grep -E '^kvm'
```

`vmx`代表Intel虚拟化扩展，`svm`代表AMD虚拟化扩展。计数大于0说明客户机能看到相关标志，但仍需用KVM宿主验证工具做完整检查。

## 1.1.7 环境基线与容量意识

嵌套实验同时占用物理机、第一层Rocky和第二层客户机的资源。资源分配应遵循“满足实验、保留宿主余量”的原则：

| 层次 | 建议 |
|---|---|
| Windows物理机 | 确保有足够内存和磁盘，不把全部逻辑处理器分给VMware |
| Rocky虚拟化宿主机 | 建议4 vCPU、6—8GB内存、80GB以上磁盘 |
| 单台KVM客户机 | 1 vCPU、1—2GB内存、10—20GB磁盘即可完成基础实验 |

常用基线命令：

```bash
hostnamectl
```

```bash
lscpu
```

```bash
free -h
```

```bash
df -hT
```

```bash
ip -brief address
```

```bash
ip route
```

## 1.1.8 CPU虚拟化如何发生

操作系统内核需要执行修改页表、处理中断、访问设备等敏感操作。没有硬件辅助时，Hypervisor必须通过复杂的软件转换识别这些操作；现代Intel VT-x和AMD-V增加了客户机运行模式，使客户机大部分普通指令可以直接在物理CPU上执行，遇到需要Hypervisor处理的事件时再退出客户机。

一次简化的执行过程如下：

```text
客户机普通应用指令
→ 直接使用物理CPU执行
→ 客户机执行敏感操作或发生外部事件
→ VM Exit退出到Hypervisor
→ Hypervisor检查并模拟、拒绝或完成操作
→ VM Entry返回客户机继续执行
```

VM Exit不是错误，但频繁退出会带来开销。虚拟设备类型、中断方式、定时器和工作负载都会影响退出次数。因此虚拟化性能不是简单由“给了几个vCPU”决定。

### vCPU与物理CPU

vCPU是Hypervisor交给客户机的可调度处理器。多个vCPU最终由宿主机Linux调度到物理逻辑处理器上：

```text
客户机进程
→ 客户机内核调度到vCPU
→ QEMU/KVM线程
→ 宿主机内核调度到物理CPU
```

为虚拟机分配8个vCPU，并不意味着它独占8个物理核心。vCPU数量超过宿主机可用能力时会发生等待和竞争。教学机同时运行Windows、VMware、Rocky和KVM客户机，更应避免过度分配。

## 1.1.9 内存虚拟化

客户机看到的是客户机物理地址，真正内存由宿主机管理。现代CPU通过EPT或NPT等二级地址转换协助完成“客户机虚拟地址—客户机物理地址—宿主机物理地址”的映射。

```text
客户机虚拟地址
→ 客户机页表
→ 客户机物理地址
→ EPT/NPT二级转换
→ 宿主机物理地址
```

虚拟机定义中的内存是可用上限或启动配置，实际宿主机还要承担QEMU进程、页表、缓存和设备模型开销。生产环境可能使用内存超分、气球设备、大页和NUMA优化；本课程只要求理解资源不能凭空产生，并能从宿主机与客户机两侧检查内存。

## 1.1.10 I/O虚拟化与virtio

客户机需要磁盘、网卡、控制台和随机数等设备。完全模拟真实硬件兼容性好，但每次设备访问都可能需要较多模拟。virtio让客户机使用面向虚拟化的驱动与Hypervisor交换数据，通常比模拟旧式硬件效率更高。

| 设备 | 常见virtio形式 | 作用 |
|---|---|---|
| 磁盘 | virtio-blk、virtio-scsi | 提供虚拟块设备 |
| 网卡 | virtio-net | 提供高效虚拟网络接口 |
| 内存 | virtio-balloon | 协助调整客户机可用内存 |
| 控制台 | virtio-console | 提供客户机控制通道 |
| 随机数 | virtio-rng | 向客户机提供熵来源 |

使用virtio通常要求客户机系统包含相应驱动。教师基础镜像必须提前验证驱动和启动方式，不能只确认镜像文件存在。

### 本章小结

虚拟化把物理资源抽象为可独立分配的虚拟硬件；嵌套虚拟化使学生能够在现有VMware实验环境中继续学习KVM。实验开始前必须验证硬件能力、软件设置与资源余量，不能把“命令执行过”误当成“环境可用”。
