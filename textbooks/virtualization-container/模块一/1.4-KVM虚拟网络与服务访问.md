## 1.4.1 虚拟网络的组成

一条从客户机到外部网络的访问路径可能经过：

```text
客户机应用
→ 客户机虚拟网卡
→ tap接口
→ Linux网桥
→ 宿主机转发/NAT或物理网卡
→ 目标网络
```

每一层都有地址、链路状态、路由和防火墙，因此“能ping通”或“网卡是UP”都只能证明链路的一部分。

## 1.4.2 libvirt NAT网络

libvirt的默认网络通常提供私有网段、DHCP、DNS转发和NAT。客户机能够主动访问外部网络，但外部主机通常不能直接访问客户机私有地址。

```bash
sudo virsh net-list --all
```

```bash
sudo virsh net-info default
```

```bash
sudo virsh net-dumpxml default
```

```bash
sudo virsh net-dhcp-leases default
```

网络对象与虚拟机对象独立：网络未启动时，即使虚拟机定义中的网卡仍引用它，客户机也无法正常接入。

## 1.4.3 桥接网络

桥接可让虚拟机通过宿主机桥接到上游二层网络，看起来像网络中的独立主机。桥接是否可用取决于机房交换网络、无线网卡限制、安全策略和地址分配方式。在教学机房不应为了展示概念擅自改动上联网络；本课程以libvirt NAT网络完成必做实验，桥接作为拓展理解。

## 1.4.5 服务验证必须跨层

以HTTP服务为例，完整证据链包括：

1. 服务进程已启动；
2. 服务器内部有端口监听；
3. 本机能够访问；
4. 同一虚拟网络中的另一台虚拟机能够访问；
5. 页面内容或API响应正确；
6. 服务日志记录了远端请求。

下面是证据链的命令格式，中文词需要替换成实验中的真实服务、地址和端口，不能原样执行：

```text
systemctl status 服务名
ss -tlnp
curl --fail http://127.0.0.1:端口/
curl --fail http://服务器地址:端口/
journalctl -u 服务名 -n 30
```

## 1.4.6 故障注入与恢复

教学中的网络故障注入必须满足三个条件：范围明确、能够回退、恢复后重新验证。可以暂时断开某台实验虚拟机的虚拟网卡，观察现象并恢复，而不应修改机房物理网络。

标准记录表：

| 阶段 | 应记录内容 |
|---|---|
| 正常基线 | 地址、路由、网卡、服务响应 |
| 故障操作 | 改了哪个对象、何时修改 |
| 故障现象 | 哪一层失败、原始错误信息 |
| 定位依据 | 使用的命令、日志或对照结果 |
| 恢复操作 | 如何恢复原状态 |
| 恢复验证 | 原验证链是否全部重新通过 |

## 1.4.7 tap、网桥与数据帧路径

QEMU为虚拟机网卡连接一个宿主机侧接口，常见形式是tap。tap像一根从虚拟机伸到宿主机网络栈的虚拟网线，Linux网桥则像软件交换机，把多个接口连接在同一二层网络中。

```text
客户机eth0
↕ virtio-net
QEMU/tap接口
↕
virbr0软件网桥
├── 另一台虚拟机tap
└── 宿主机IP、DHCP/DNS及NAT转发
```

虚拟机网卡在客户机中显示UP，只证明客户机侧接口启用；tap可能断开、网桥可能未启动、libvirt网络可能无DHCP，外部访问仍会失败。

## 1.4.8 NAT、桥接与路由模式对比

| 模式 | 客户机地址来源 | 外部主动访问 | 适用场景 | 主要风险或限制 |
|---|---|---|---|---|
| NAT | 私有网段DHCP或静态地址 | 通常需端口转发 | 教学、开发、普通出网 | 外部不能直接到达客户机 |
| 桥接 | 上游网络分配 | 可能直接访问 | 需要虚拟机成为局域网主机 | 受机房网络、无线和安全策略限制 |
| 路由 | 独立子网并配置路由 | 由路由策略决定 | 数据中心受控网段 | 需要上游路由和防火墙配合 |
| 隔离网络 | 私有地址 | 不允许 | 恶意样本、后端隔离、内部测试 | 无法直接访问外部依赖 |

模式选择不是越开放越好，而是由访问方向、地址规划、隔离需求和机房权限共同决定。

## 1.4.9 DHCP、MAC与地址稳定性

DHCP通常根据虚拟网卡MAC识别客户端。克隆时如果MAC重复，可能发生租约冲突；MAC改变后，客户机地址也可能改变。需要稳定管理地址时，可以在libvirt网络中配置DHCP保留，或在客户机内设置静态地址，但两者都必须避免落入DHCP动态分配范围造成冲突。

排障时建立对应表：

| 虚拟机 | libvirt名称 | 网卡MAC | 客户机接口 | IP地址 | 网络对象 |
|---|---|---|---|---|---|
| course-vm01 | course-vm01 | 实际值 | eth0或ens3 | 实际值 | default |

## 1.4.10 四层与七层验证

ICMP通只表示基本IP路径可用；TCP连接成功说明目标端口能够建立连接；HTTP状态和内容正确才说明应用层达到预期。常用验证层次：

```text
链路：ip link
→ 地址：ip address
→ 路由：ip route
→ 邻居：ip neigh
→ IP：ping
→ TCP：nc或curl连接
→ HTTP：状态码、响应体
→ 应用：业务数据
→ 日志：服务端记录
```

遵循此顺序可以缩小故障范围。直接从“网页打不开”跳到重装Nginx，会丢失大量定位信息。

### 本章小结

虚拟网络不是一个“联网开关”，而是一条由虚拟网卡、tap、网桥、转发、地址、路由和防火墙组成的路径。排障要由近到远、由链路到应用，最终以真实服务响应证明交付成功。

### 本章短练习：只读导出默认网络摘要

先创建练习目录：

```bash
mkdir -p ~/course-practice/vc-m1/ch04
```

把网络列表写入摘要文件：

```bash
sudo virsh net-list --all > ~/course-practice/vc-m1/ch04/default-network-summary.txt
```

依次追加网络详情、租约、宿主机虚拟接口和路由：

```bash
sudo virsh net-info default >> ~/course-practice/vc-m1/ch04/default-network-summary.txt
```

```bash
sudo virsh net-dhcp-leases default >> ~/course-practice/vc-m1/ch04/default-network-summary.txt
```

```bash
ip -brief address | grep -E 'virbr|vnet' >> ~/course-practice/vc-m1/ch04/default-network-summary.txt
```

```bash
ip route >> ~/course-practice/vc-m1/ch04/default-network-summary.txt
```

查看最终摘要：

```bash
less ~/course-practice/vc-m1/ch04/default-network-summary.txt
```

在输出中找出网络名称、是否活动、是否自启动、网桥、地址段和租约。短练习不停止、重定义或删除网络；正式两机访问和链路故障在实验4完成。
