# 课程交互动画

本目录保存《Linux操作系统》和《虚拟化容器技术》的离线交互动画。动画用于解释对象关系、数据流和状态变化，不替代教材、命令练习或项目实验。

## 使用方法

1. 进入某个动画目录。
2. 双击`index.html`，使用Chrome、Edge或Firefox打开，不需要安装Web服务器。
3. 投影时按`F11`进入全屏。
4. 先提出动画页右侧的“观察任务”，再播放或单步演示。

所有动画应保持纯本地运行，不引用CDN、在线字体和远程图片。

## 动画01课堂使用顺序

1. 先切换桥接、NAT、仅主机，要求学生只根据拓扑判断可达范围。
2. 回到NAT，逐步播放同网段通信、出站地址转换和外部主动访问限制。
3. 强调页面中的地址只是概念示例：实验1使用DHCP发现并记录实际VMnet8参数，实验8才统一配置静态地址。
4. 进入Linux实验1前回答“为什么课程初装选NAT”；进入虚拟化容器实验4时再次打开，比较VMware网络与libvirt网络。

## 动画02课堂使用顺序

1. “目录树与/bin”：区分`/`和`/root`，按用途认识目录，观察usr-merge与挂载。
2. “绝对/相对路径”：每一步先遮住结果，让学生根据当前工作目录计算最终目标。
3. “inode与链接”：先预测inode号、硬链接计数和删除原名后的可读性，再到Rocky执行`ln`、`ln -s`、`ls -li`和`stat`。
4. 前两个主题在Linux实验2使用，第三个主题在教材第5章和Linux实验3使用。

## 动画03课堂使用顺序

1. “身份与匹配”：强调owner、group、other只选择一组，不叠加权限。
2. “文件/目录rwx”：重点比较目录的`r`、`w`、`x`，以及删除由父目录权限决定。
3. “chmod与umask”：从权限位理解数字，不把umask简单理解成任意十进制减法。
4. “共享目录”：预测SGID、umask、Sticky和ACL组合后的允许与拒绝，再进入实验4用四个真实账号验证。

## 动画04课堂使用顺序

1. “运行与自启”：分别推演`start`、`enable`、`enable --now`，区分active和enabled。
2. “依赖与顺序”：比较Wants、Requires与After，避免把“需要谁”和“谁先执行”混为一谈。
3. “进程与信号”：观察MainPID、服务cgroup、SIGTERM、超时后SIGKILL以及reload/restart差异。
4. “日志证据链”：用实验6的错误ExecStart场景完成status、show、journal、路径验证、最小修复和三层复测。
5. 实验14部署Nginx时复用第一、第四主题，先检查配置语法，再选择reload或restart。

## 动画05课堂使用顺序

1. “设备与连接”：区分NetworkManager的device、connection profile和激活后的运行状态。
2. “路由与网关”：先按最长前缀选择路由，再判断同网段目标或默认网关的下一跳。
3. “名称解析”：比较NSS、hosts、有效解析器、DNS以及`getent`和`dig`。
4. “分层排障”：依次检查链路、地址、路由/网关、DNS、端口/服务；每一步只根据证据处理一个根因。
5. 实验8完整使用，实验9复用名称解析，实验13复用分层排障。

## 动画06课堂使用顺序

1. “Socket与监听”：从进程、协议、本地地址和端口识别监听，比较回环、具体地址和通配地址。
2. “TCP连接”：观察四元组、三次握手、监听/已连接Socket以及refused和timeout。
3. “HTTP消息”：按名称解析、TCP、请求行、Host、URI、状态码和响应内容逐层推进。
4. “TLS握手”：区分TCP连接、ClientHello/SNI、证书SAN与信任链、密钥协商和加密HTTP。
5. 实验9完整使用；实验14复用HTTP虚拟主机、location、404和502部分。

## 动画07课堂使用顺序

1. “主机身份”：先把TCP连通与SSH可信分开，再通过VMware控制台核对首次连接指纹。
2. “用户认证”：区分主机密钥和用户密钥，观察公钥部署、私钥签名、服务端验签和权限拒绝。
3. “配置与命令”：比较专用`Host`与`Host *`的顺序，用`ssh -G`确认最终参数，再判断远程命令的展开位置。
4. “文件传输”：根据冒号判断SCP方向，区分SFTP本地/远程命令，并用SHA256形成完整性证据。
5. 实验10完整使用；实验13复用`ssh -vv`与服务端journal组成的双端证据链。

## 动画08课堂使用顺序

1. “路径语义”：先展示固定源和目标，再分别预测`web/`与`web`产生的目标目录树。
2. “增量与删除”：比较首次、再次同步和`--checksum`，强调普通同步保留目标多余项，`--delete`必须先预演。
3. “定时执行”：读取五个时间字段，比较交互终端与cron环境，并把绝对路径、日志、退出码和`flock`串起来。
4. “恢复验证”：先恢复到隔离目录，再完成内容、元数据与业务检查；区分当前镜像和历史恢复点。
5. 实验11完整使用；模块三数据库备份与综合项目可复用“备份—日志—恢复—验证”证据闭环。

## 动画09课堂使用顺序

1. “流量与Zone”：从Ubuntu数据包进入Rocky开始，判断接口、活动zone和规则，不把默认zone当作接口实际归属。
2. “Service与Port”：区分预定义service、明确端口、应用启动和监听地址，组合一次完整访问的必要条件。
3. “运行时与永久”：分别推演两套状态和reload，按“运行时验证—永久化—reload—再次验证”完成变更。
4. “来源限制与回滚”：用实际客户端源地址构造rich rule，展示宽允许规则不会被窄允许规则覆盖，并完成正反向验证。
5. 实验12用于规则配置与回滚；实验13用于“本机成功、外部失败”等故障的分层定位。

## 动画10课堂使用顺序

1. “DAC与MAC”：识别主体、对象和操作，分别判断传统权限与SELinux策略，强调两类控制必须同时允许。
2. “模式与上下文”：比较Enforcing、Permissive、Disabled，并拆解`user:role:type:level`，重点观察类型强制。
3. “标签持久化”：比较`chcon`当前标签、`semanage fcontext`路径映射与`restorecon`实际应用。
4. “AVC排障”：从可重复现象出发，读取主体域、目标类型、对象类别和拒绝权限，再选择已有策略支持的最小修复。
5. 实验12用于标签创建与恢复；实验13用于分层排障；实验14复用非标准Web目录和反向代理策略判断。

## 动画11课堂使用顺序

1. “受理与基线”：把模糊报障转换为客户端、目标、方法、错误和范围，并与成功基线比较。
2. “分层证据”：沿名称、路由、TCP、服务、监听、防护和应用层选择能支持或排除假设的最小证据。
3. “故障模式”：比较多服务同时失败、名称/IP差异、refused、本机成功外部失败及高层权限拒绝。
4. “修复闭环”：一次只修改一个被证据支持的对象，从原客户端按原方式复测，再检查第二故障和最终基线。
5. 实验13完整使用；实验20用于三机综合链路的逐跳定位和故障报告。

## 动画12课堂使用顺序

1. “监听与Server”：先验证TCP 80监听，再根据Host选择虚拟主机；强调`server_name _`并不会自动成为默认站点。
2. “Location与路径”：比较精确和前缀location，计算`root + URI`的最终路径，并区分`alias`与`try_files`。
3. “反向代理”：观察客户端、Nginx和上游两段连接，比较`proxy_pass`有无URI尾斜杠时的上游路径。
4. “状态码与日志”：用200、403、404、502缩小方向，并把access log、error log和直接上游验证组合起来。
5. 实验14完整使用；实验20把本机上游扩展为`rocky-web → rocky-server`跨主机代理。

## 动画13课堂使用顺序

1. “对象与连接”：认识实例、数据库、表、行列和工具，比较Unix Socket、本机TCP与远程TCP入口。
2. “远程访问边界”：依次判断`bind-address`、firewalld来源、账号Host和SQL操作权限，并完整回收临时开放。
3. “账号与授权”：比较同名不同Host账号，用`USER()`与`CURRENT_USER()`确认实际匹配行，同时验证允许和拒绝操作。
4. “备份与恢复”：识别重定向产生空文件的风险，理解`--single-transaction`边界，先恢复到测试库再比较数据。
5. 实验15完整使用；实验20复用本机监听、最小权限、逻辑备份和恢复抽查。

## 动画14课堂使用顺序

1. “文档模型”：区分数据库、集合、文档、字段和`_id`，比较嵌套对象、数组与关系表，并解释首次写入后才物化。
2. “认证数据库”：按仅本机初始化、创建用户、启用`authorization`的顺序推进，区分用户身份所在库和默认业务库。
3. “RBAC与监听”：比较Authentication failed和Unauthorized，验证允许和拒绝操作，并说明`bindIp: 127.0.0.1`下远程失败是预期结果。
4. “备份与恢复”：认识BSON与集合元数据文件，检查备份非空，先恢复到隔离测试库；未经确认不对唯一业务库使用`--drop`。
5. 实验16完整使用；实验20复用本机监听、认证查询、`mongodump`和恢复抽查。

## 设计约定

- 蓝色表示主机或虚拟机，紫色表示虚拟交换/虚拟化组件，绿色表示可达目标，红色表示被阻断。
- “播放”用于连续说明，“上一步/下一步”用于课堂提问和学生预测。
- 页面显示的是帮助理解的概念模型，最终地址、网卡名和验证结果以实验环境为准。
