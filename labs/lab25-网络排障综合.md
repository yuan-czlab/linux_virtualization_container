## 一、十步排障流程

```
服务访问不了？
  □ ① ping 127.0.0.1    → 本机网络栈是否正常
  □ ② ip a              → IP 配置是否正确
  □ ③ ping 网关          → 局域连通性
  □ ④ ping 外网 IP       → 外网连通性
  □ ⑤ ping 域名          → DNS 是否正常
  □ ⑥ systemctl status   → 服务是否运行
  □ ⑦ ss -tlnp           → 端口是否监听
  □ ⑧ curl localhost:端口 → 本机是否可访问
  □ ⑨ firewall-cmd       → 防火墙是否放行
  □ ⑩ ausearch / journalctl → SELinux/日志报错
```

教师从以下 5 个故障中选 3 个注入。学生按 10 步流程排查，**记录每一步的输出和判断**。

| # | 教师注入 | 现象 |
|---|---------|------|
| F1 | `sudo systemctl stop nginx` | curl 拒绝连接 |
| F2 | `sudo firewall-cmd --remove-service=http --permanent && reload` | 本机curl通，外部不通 |
| F3 | `sudo chcon -t user_home_t /usr/share/nginx/html/index.html` | 403 |


## 七、常见问题

**Q: 排障时先查什么后查什么？**
A: 从底层往上层查：物理/虚拟层 → 网络层(IP) → 传输层(端口) → 应用层(服务) → 安全层(防火墙/SELinux)。底层不通上层肯定不通。

**Q: 排障卡住了怎么办？**
A: ①缩小范围：是只影响单个用户还是所有用户？②对比法：另一台正常机器同样操作是否OK？③二分法：逐一排除。④查日志是最直接的。

**Q: 为什么故障修复后要写排障报告？**
A: ①复盘防止再犯；②团队知识积累；③面试时这是最好的"项目经验"素材；④出了问题有迹可循。
