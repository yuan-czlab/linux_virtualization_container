# 实验手册格式规范

> 所有实验文件遵循此模板。每个实验 = 一个 .md 文件，放在 labs/ 目录下。

---

## 文件命名

```
labXX-简短描述.md
例：lab14-权限场景练习.md
```

编号与 `01-unit-index.md` 中的 Lab 编号一致。

---

## 内容结构（每个实验必须包含以下段落）

```markdown
# LabXX：实验名称

> 课时：X | 类型：个人/双人 | 前置：LabXX（或"无"）

## 一、你会学到什么
- 用学生能理解的语言写 3-5 条，每条以动词开头（"能..."、"会..."）
- 不写"理解xxx概念"，写"能独立完成xxx操作"

## 二、原理速览
- 用3-5条说明对象、工作机制、关键依赖和安全边界
- 至少提出1个需要学生在实验后回答的“为什么”问题
- 详细理论讲授以 `course-design/14-课堂实施与理论讲授指南.md` 为准

## 三、实验环境
- 明确写出需要的 VM、软件、账号
- 如果用到特定 IP 或主机名，写清楚

## 四、实验拓扑（如果需要）
- 用 ASCII 图画出网络/架构关系

## 五、实验步骤

### 步骤1：xxx（简短标题）
每步包含：
1. 要做什么（一句话）
2. 具体命令（代码块，学生可以直接复制）
3. 预期输出（关键行的代码块）

> **验收点**：这一步做完你应该看到什么 / 运行什么命令验证

### 步骤2：xxx
...

## 六、验收标准
- [ ] 明确可检查的条目，学生自检用，教师巡堂打分用
- [ ] 至少 3 条

## 七、常见问题
Q: 遇到的问题描述
A: 解决方法

## 八、清理环境（如果需要）
- 删除本次实验创建的资源，避免影响下次实验
```

---

## 写作原则

1. **命令必须可复制**。不放截图代替命令文本。
2. **每步都有验收点**。学生不知道自己做得对不对，验收点就是"对的标准"。
3. **故意埋雷**。部分实验步骤会故意让学生遇到错误，然后引导排错（标注 ⚠️ 陷阱）。
4. **错误是教学内容**。常见问题部分要写真实会遇到的坑，不要只写"注意不要打错命令"这种废话。
5. **命令给全，不缩水**。不要写"使用 vim 编辑配置文件"，要写 `sudo vim /etc/nginx/nginx.conf`。
6. **先讲机制再操作**。实验手册至少说明命令改变了什么对象，以及如何验证结果。
7. **控制90分钟负载**。标明核心步骤和拓展步骤，核心验收必须能在课堂时间内完成。
