### 步骤2：快照原理（Copy-on-Write）

```
拍快照前：基础磁盘
  基础磁盘 (base.vmdk) - 所有数据都在这里

拍快照后：
  基础磁盘 → 只读
  增量磁盘 (snapshot-001.vmdk) → 所有新写入都写到这里
  
恢复快照 = 丢弃增量磁盘，基础磁盘回到只读时的状态
删除快照 = 把增量磁盘合并到基础磁盘

⚠️ 快照不能替代备份！
  - 基础磁盘物理损坏 → 快照也没用
  - 长期保留多级快照 → 影响性能
  - 实验前拍快照，实验后删除
```

### 步骤3：完整克隆 vs 链接克隆

```text
在 VMware 中对比两种克隆：

完整克隆：
  创建 → 类型：创建完整克隆
  结果：独立的完整副本，克隆后与原 VM 完全无关
  时间：慢（复制几十 GB 磁盘）
  空间：占用大

链接克隆：
  创建 → 类型：创建链接克隆
  结果：共享父 VM 的磁盘，只存自己的差异数据
  时间：快（几秒）
  空间：占用小
  限制：父 VM 必须在且可用
```

### 步骤4：制作模板机

```bash
# 在 web-server 上，清理个性化信息使其成为模板
sudo hostnamectl set-hostname template

# 清除 SSH 主机密钥（克隆后首次启动会自动重新生成）
sudo rm -f /etc/ssh/ssh_host_*

# 清除机器 ID（克隆后自动生成）
sudo rm -f /etc/machine-id
sudo echo "" > /etc/machine-id  # 创建空文件，首次启动时 systemd 会填充

# 清除网络配置中的 MAC 地址绑定
sudo nmcli con show | grep -v NAME | awk '{print $1}' | while read conn; do
    sudo nmcli con mod "$conn" connection.interface-name ""
done 2>/dev/null

# 清理包缓存
sudo dnf clean all

# 清理日志
sudo rm -rf /var/log/*.log /var/log/*/*.log

# 关机（不要再启动！）
sudo poweroff
```

以后需要新 VM 时，从这台模板机克隆，首次启动会自动：
- 生成新的 SSH host key
- 生成新的 machine-id
- 检测和配置网卡

## 七、常见问题

**Q: 快照能替代备份吗？**
A: 不能。快照存在同一个物理磁盘上，磁盘损坏则快照也丢失。快照是"快速回滚"，备份是"灾难恢复"，两者互补。

**Q: 快照太多会影响性能吗？**
A: 会。多级快照形成长链，每次读写都要遍历快照链，磁盘 IO 性能下降。实验完成后及时删除不需要的快照。

**Q: 模板机为什么需要清除 SSH host key？**
A: 每台机器的 SSH host key 应该唯一（用于验证服务器身份）。克隆出来的 VM 如果不重新生成 host key，两台机器有相同的 host key，SSH 客户端会告警"指纹冲突"。
