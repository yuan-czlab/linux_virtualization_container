# 《虚拟化容器技术》实验手册编写规范

> 本规范适用于64学时《虚拟化容器技术》的11个实验项目。
>
> 实验文件使用`lab01`—`lab11`编号，与课程实验项目索引一致。

## 一、实验手册定位

实验手册供学生独立学习和完成项目，也作为教师课堂演示、巡回指导、故障注入和验收依据。

- 学习通分章教材系统讲解知识、原理、对象关系、风险和方法；11章分别与实验1—11一一对应。
- 实验手册提供完成项目所需的环境、任务、详细操作、预期结果、验证、排障和交付要求。
- 实验手册不按每次到课机械拆分；同一实验可以在授课计划中跨越多次课。
- 所有外部地址、账号和镜像使用明确占位符，并在开课前由教师统一发布实际值。
- OpenStack和Kubernetes均有正式实验任务，但使用教师预建平台，不在本课程搭建集群。

## 二、统一环境名称

| 名称 | 含义 | 主要用途 |
|---|---|---|
| Windows宿主机 | 学生机Windows 10/11 | 运行VMware Workstation和保存课程资源 |
| `rocky-server` | Linux课程保留的Rocky Linux 9，用户`rocky-server` | KVM宿主机、Docker环境A |
| `ubuntu-client` | Linux课程保留的Ubuntu 22.04 Desktop，用户`ubuntu-client` | Docker环境B、主要Compose目标 |
| `rocky-web` | Linux课程保留的Rocky Linux 9，用户`rocky-web` | 默认关机保留；按教师安排参与外部Web验证 |
| KVM客户机 | 在`rocky-server`中创建的轻量Linux虚拟机 | KVM生命周期、镜像、网络和恢复；教师镜像内账号另行发布 |
| 课程镜像仓库 | `<COURSE_REGISTRY>` | 学校服务器中的Docker镜像分发地址 |
| 课程镜像标签 | `<COURSE_TAG>` | 教师发布的本学期固定标签，不使用`latest` |
| 离线资源目录 | `<COURSE_MEDIA>` | U盘或机房共享目录中的软件包、qcow2和Docker归档 |
| OpenStack平台 | `<OPENSTACK_URL>` | 教师提供的云主机体验平台 |
| Kubernetes集群 | `<K8S_CONTEXT>` | 教师提供的容器编排体验集群 |
| Kubernetes命名空间 | `<K8S_NAMESPACE>` | 教师为学生个人或小组分配的Namespace |
| Kubernetes课程镜像 | `<K8S_IMAGE>` | 集群能够拉取的固定版本应用镜像 |

占位符必须替换后再执行，不能把尖括号原样复制到终端。

```markdown

> 项目成果：
```

“知识前置”说明需要理解的前序知识；“状态依赖”只列出必须真实存在的VM、qcow2、libvirt网络、镜像、卷、源码或Compose项目。“建议起点”填写`VC-V0`—`VC-V3`中的最近检查点。实验开始时必须检查继承对象；对象缺失时恢复检查点或执行手册给出的准备步骤，不能临时使用来源不明的镜像或同名空文件代替。

## 四、详细程度

每个关键步骤应说明：

1. 为什么执行。
2. 在哪台主机执行。
3. 命令或界面如何操作。
4. 正常结果应出现什么关键内容。
5. 使用什么独立证据证明有效。
6. 出错时按什么顺序检查。
7. 如何恢复到已知状态。

学生需要执行的命令必须可复制；使用`<实际值>`的命令必须紧邻解释。不能仅写“配置网络”“安装Docker”“创建实例”等无法独立完成的笼统步骤。

当前实验使用的目录必须在第一次写入前创建；复制、修改、校验或删除既有文件前，必须先确认精确对象存在。对前序实验产物的依赖应在实验开头失败得清楚，不能执行到中段才出现“No such file or directory”。

学生立即执行的常规命令原则上一条一块，并在相邻文字中说明目的和观察点。配置文件、Dockerfile、Compose YAML和Kubernetes YAML应让学生使用编辑器创建，再用对应语言代码块展示内容，不放进Shell here-document中一次生成。只有批量状态采集、校验或交付确实需要自动化时，才使用短小Shell脚本；脚本应在学生掌握组成命令后逐步形成，不能替代虚拟机、镜像、网络、卷、Compose和Kubernetes对象的核心操作。

## 五、安全与可恢复规则

- 删除虚拟机、镜像、容器、卷和OpenStack/Kubernetes资源前必须先列出精确目标。
- 不使用模糊通配符和未赋值变量执行删除。
- 不在实验中关闭SELinux或防火墙作为标准修复方法。
- 不使用`chmod 777`解决容器挂载权限问题。
- Docker组成员具有接近root的主机控制能力，教材和实验必须明确风险。
- 密码、私钥、Registry Token、OpenStack凭据和kubeconfig不得提交到Git。
- 操作基础qcow2前先复制；教师基础镜像始终保持只读。
- 数据卷删除、Compose清理和Kubernetes资源删除必须在指定课程命名空间或项目目录内进行。

## 六、验证证据

每个实验至少覆盖以下两类证据，综合实验应覆盖全部：

- 状态：服务、虚拟机、容器、Pod是否处于预期状态。
- 配置：实际生效的XML、Compose或YAML是否正确。
- 网络：地址、路由、名称解析、端口和跨主机访问是否成立。
- 功能：应用是否从使用者路径返回正确结果。
- 日志：请求、启动或故障是否形成可解释日志。
- 数据：容器、卷或数据库重建后数据是否保持或恢复。
- 校验：镜像归档、qcow2或交付包的SHA256是否一致。
- 回退：错误修改后是否可以恢复到基线。

## 七、课程资源版本规则

1. 教师每学期发布《课程软件与镜像清单》，固定Docker Engine、Compose、qcow2、基础镜像和应用镜像版本。
2. 实验手册使用语义化课程标签，例如`course/web:v1`，实际仓库前缀由教师发布。
3. 不使用`latest`作为正式验收依据。
4. 在线仓库和离线包必须对应同一镜像摘要。
5. 教师开课前分别在Rocky和Ubuntu验证所有Docker镜像，在KVM环境验证qcow2镜像，在预建平台验证OpenStack和Kubernetes任务。
