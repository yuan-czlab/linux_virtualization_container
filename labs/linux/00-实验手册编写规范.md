# 《Linux操作系统》实验手册编写规范

> 本规范适用于64学时《Linux操作系统》的20个实验项目。  
> 实验文件使用`lab01`—`lab20`编号，与课程实验项目索引一致。

## 一、实验手册定位

实验手册供学生独立学习和完成项目，也作为教师课堂演示、指导和验收的操作依据。

- Textbooks系统讲解知识、原理和方法。
- 实验手册提供完成项目所需的知识摘要、环境、任务、完整操作、验证和排障方法。
- 实验手册不复制教材中的大段理论，也不能退化为没有解释的命令清单。
- 实验手册不按具体课次机械划分阶段；授课进度由课程进度表安排。

## 二、文件命名

```text
lab01-Linux系统认知与三机环境安装.md
lab02-Linux命令行与文件目录管理.md
……
lab20-Linux企业服务器综合项目.md
```

统一环境为`rocky-server`、`rocky-web`和`ubuntu-client`。实验2—13默认在`rocky-server`操作，实验14明确切换到`rocky-web`，实验15—19返回`rocky-server`，实验20使用三机完成综合交付。

## 四、实验步骤写作要求

每个关键步骤应尽量说明：

1. 操作目的：为什么做这一步。
2. 操作方法：完整命令、配置或界面操作。
3. 关键解释：对象、参数和风险。
4. 预期结果：学生应该看到的关键状态。
5. 验证方法：用另一条命令、另一个账号或客户端证明结果有效。
6. 常见异常：高频错误及检查方向。

示例：

````markdown
### 步骤：查看发行版信息

执行：

```bash
cat /etc/os-release
```

重点观察`NAME`、`VERSION`和`ID`。该命令显示发行版信息，不是Linux内核版本。

继续执行：

```bash
uname -r
```

> **验收点**：分别记录发行版版本和内核版本，并用一句话说明二者的区别。
````

## 五、命令和配置规范

- 所有学生需要执行的命令必须可复制。
- 使用`<实际值>`表示必须替换的内容，并紧邻命令解释替换方法。
- 不在示例中放置真实密码、私钥、Token或生产地址。
- 高风险命令必须使用明确、可验证的实验目录。
- 涉及覆盖、删除、网络、SSH、防火墙和服务配置时，先检查目标并保留回退方法。
- 修改配置后先做语法检查或有效配置检查，再reload或restart。
- 不能使用“关闭防火墙”“关闭SELinux”或`chmod 777`作为标准修复方法。

## 六、验证与验收规范

验证至少覆盖以下一种或多种证据：

- 状态：服务或资源是否处于预期状态。
- 配置：实际生效配置是否正确。
- 端口：服务是否在正确地址和端口监听。
- 功能：从使用者或客户端视角是否可以访问。
- 日志：是否有错误以及请求是否真实到达。
- 数据：写入、查询、备份和恢复结果是否一致。
- 回退：修改失败后是否能够恢复到已知状态。

每篇实验的Checklist应包含可观察、可判断的结果，避免使用“了解了”“熟悉了”等不可检查表述。

## 七、详细程度

实验手册需要足够详细，使学生能够按文档完成项目，但不追求穷举工具的全部参数。

优先详细说明：

- 为什么执行；
- 改变了什么对象；
- 正常结果是什么；
- 如何证明有效；
- 出错时先检查什么；
- 如何恢复。

理论推导、技术发展和系统比较等内容由对应Textbooks章节完整讲授，实验手册保留完成项目必需的知识摘要。
